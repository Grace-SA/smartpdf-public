# PDF → PPT 第四轮：原生区域、字体与完整回归

2026-11-12。基于 `4960a40` 的本地质量检查点，**未达到通用上线标准**。不部署 AWS、不合并 main；GitHub CI 额度不可用，提交使用 `[skip ci]`，不声称 CI 通过。扫描件新算法仍在隔离原型中，不混入本轮成绩。

## 固定样本与质量口径

保留两组公开语料各 200 份、17 份合成边界输入的身份和预期拒绝。公开有效输入 384/384 生成成功；全部公开输入口径为 384/400（96%），另外 16 个按原规则拒绝。边界集 14 个生成、3 个预期拒绝。最终 398 个 PPT、782 页全部重新打开、独立渲染、核对页数、来源哈希、恢复文字来源和字体渲染证据。

“没有可编辑文字”包括纯图和空白页，不能全部解释为转换失败；反过来，只恢复页脚也不能算整页可编辑成功。显式图片回退已经从初始 128 页降至 28 页，但这个数没有涵盖全部不可编辑输出。61 页 OCR 路径仍只有 198/3087 个检测行可编辑，28 页没有可编辑行；这不是人工真值准确率。

68 页文字参考仍为同一组 130,038 个源文字一致性筛选后的 DocLayNet 自动参考字符，不是人工扫描件转录。原先严格通过的 37 页全部保留，逐页 CER 没有恶化。但恢复更多文字同时增加了与参考区域对应不准确的预测字符，聚合精确率下降，不能只宣传召回改善。新增财务正文恢复仍有文字落在不正确参考区域的问题，尚未达到整页严格验收。

## 实现与 code review

- 增加可选 CMU 0.7.0 开放字体，用于明确标识的 Computer Modern 正文。只嵌入固定哈希的完整 regular/bold/italic/boldItalic 字体及完整 OFL 许可；不分发系统字体，也不猜测任意 PDF 字体。
- 修正连字、私用区字符被误判为中文；公式、符号字体和无法映射的私用区字形保留原图。
- 区域恢复不再因为页脚恢复成功就停止尝试正文。更细策略必须严格覆盖之前已恢复的源字形出现位置，并继续通过原有位置、区域像素和全页检查。
- 修正日期中的逗号被误作千位分组的问题；负号和前导小数点仍是数字一致性检查的一部分。
- review 找到两类实际问题并补充回归：过度保护 Symbol 字体误伤普通项目符号、单位符号；跨对象字符索引区间误计覆盖。前者改为只放行明确的 Unicode 普通符号，后者逐字核对源对象归属。
- 修复前曾出现 3 个严格通过页面退步；修复后全部恢复。没有把中间失败版本计入最终成绩。

## 测试与证据边界

后端最终 341 项通过，覆盖率 93%，包含真实 Office 渲染和可选字体；网站累计 620 项单元测试、73 个测试文件通过；Chromium/WebKit 累计浏览器回归 188 项通过。真实 API、隔离 worker、Stirling 与三种 OCR 的四条浏览器冒烟流程通过，覆盖原生/扫描输入、中文、下载、授权和删除清理。浏览器冒烟先于最后两项原生 review 修复，修复后由后端完整回归和对应固定样本重放覆盖；不声称重新运行了真实浏览器冒烟。新打包 wheel 的全部运行文件、字体目录和许可与最终源码逐字节一致，解包导入通过。

完整 417 输入先执行一轮固定上游 Stirling 与真实 OCR 缓存重放。最后两项 review 修复后，对全部 417 输入比较三种提取模式和源字形归属，确认其他运行模块一致；重跑受影响的 25 份 DocLayNet 和 11 份公开文档，其余结果保留哈希绑定的已验证输出。**全部 398 个最终输出随后再次独立渲染和核对**，不是声称修复后又新跑了每一个转换。逐样本身份、差异审计、运行源码哈希、产物和日志仅本地保存。

在并行转换、字体测试与模型推理同时运行时，最长公开样本重放 755.95 秒，超过默认 600 秒任务预算；不是端到端 SLA，也不等于生产 worker 超时验收通过。容量、排队与长文档时限仍需处理。DocLayNet 最长 220.86 秒，边界集最长 57.58 秒。

CMU 三字体族、四种字形共 12 行测试在 LibreOffice 和真实 PowerPoint for Mac 中归一化文字一致；这不代表完整跨客户端位置验收。上一轮 PowerPoint 两处扫描件位置问题仍未销项。生产 Linux、Windows PowerPoint、真实扫描件人工真值、网站正式接入和生产 CI 均尚未完成。
