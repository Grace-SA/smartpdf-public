# PDF 转 PPT：版面、字体与免费 OCR 改进

2026-11-11。状态：已实现并完成本机实验验收，仍不满足通用生产上线标准。代码位于 `server/pdf-to-ppt/`，不接入生产网站路由。此前 Stirling 3.2.2 及其 Office→PDF 生产配置未改变。

## 本轮追加：OXR、适用范围与上线判定

项目方已确认符合 OXR 当前免费使用条件，已接入本地 OXR 1.0 + D-FINE 处理流程。PDF→PPT 验收页底部列出 PaddleOCR、Unlimited OCR 2 和链接到官方仓库的 **Powered by SoMark OXR**。配置决定实际启用的引擎；没有声称每次转换都运行三种模型。[OXR 官方许可](https://github.com/SoMarkAI/OXR/blob/main/LICENSE)及完整通知保留在模块 `ocr/licenses/`。GitHub CI 因账户额度暂不可用，本轮使用本地检查，未将远端 CI 标记为成功，也未部署。

### 已落地的改进

- Paddle 提供逐行定位与文本；U2/OXR 按同一图像 SHA-256、尺寸及区域坐标复核。文字顺序和数字必须在对应区域一致；整页字符多重集相同不能批准替换。配置两个复核器时取共同通过部分；没有独立复核器则保留扫描原图。
- 一处识别分歧只阻止对应区域。完全重合且文本相同的 OXR 重复页脚可合并；冲突区域、重叠 OCR 擦除框、截断输出不批准编辑。
- 对简单 HTML 网格，核对每行每列的原文、数字、空间对齐和贯穿区域的列间空隙，允许恢复定位文本框。空白/合并/多行单元格及复杂公式不据此重建，保留图像；不把文本框宣称为原生表格。
- 均匀浅色纸张和文字颜色可保留；拉丁字形在已安装的 Arial、Times New Roman、Courier New 及其粗体候选之间受控匹配。匹配不明确时报告字体未知，避免单凭 CJK 字高推断粗体。仍没有字体嵌入，无法承诺客户端字体一致。
- 原生文字出现已知字符/数字恢复缺失时，相关页退回原稿图像，下载前列出不可编辑页；原始错误指标和失败路线留在 `content_gate`。这些页计为恢复失败/兜底，绝不计作可编辑恢复成功。
- 源码/模型固定大小与 SHA-256；OXR 检测器只连回环地址。OXR 生成的图块、OCR 图片和 LibreOffice 临时资料归任务目录管理，取消/过期时一起清理。

### 通用上线门槛：未通过

目前是**内部验收版**，不是通用上线候选。主要阻断项：

1. 内容恢复覆盖率不足：固定公开集约 30% 的有效文档含整页兜底，扫描复杂表、倾斜/旋转页和字体风格仍有限。需要更广且有人工作为真值的真实业务样本验证，不能以 9 个合成类型通过外推通用性。
2. 生产运行时尚未验收：U2/OXR 当前只验过 Mac MLX；Linux/服务器镜像、实际字体交付、稳定 LibreOffice、并发与容量、上游取消及临时文件清理尚未完成。本地计算免费不等于无需服务器资源。
3. 网站集成与用户验收尚未完成：当前独立页未接入主站生产任务系统；缺生产鉴权/限流/配额与完整浏览器、PowerPoint/WPS、真实设备验收。本轮没有浏览器自动化或真实设备测试。

页面仍显示 development preview、所有可编辑任务仍为 `needs_review`。发布前须补齐上述项，并按仓库发布规则处理 CI 暂停期间的发布门禁及显式发布授权；本轮未请求部署、未修改发布门禁、未合并主分支。

## 选型结论

采用 **原生 PDF 文字与坐标优先、PaddleOCR v6 按需识别、Unlimited OCR 2 可选复核、独立渲染逐页准入**。不把所有 PDF 栅格化后重新识字，也不让模型猜改原 PDF 已经明确的数字。

| 候选 | 核对和实测 | 当前角色 |
| --- | --- | --- |
| PP-OCRv6 medium | 官方 ONNX 检测与识别模型，模型卡 Apache-2.0；RapidOCR 3.10.0 + ONNX Runtime 1.31.1 在本机 CPU 实测 | 默认扫描文字定位/识别，可不使用 GPU，无付费 API |
| Unlimited OCR 2 | 官方权重卡 MIT；复用此前已验证 BF16 MLX 权重，在相同图像上重新推理 | 可选独立内容/结构证据；分歧时保留原图而非自动猜改 |
| PaddleOCR-VL-1.6 | 重新核对官方模型卡，Apache-2.0，支持 OCR/table/spotting 等任务 | 本轮只做资料核对，未推理，不宣称其实际效果或性能 |
| OXR | 复核现行 LICENSE：Apache 2.0 加附加商业规模和署名条件；此前本机结构识别有研究结果 | 不进入无条件免费默认依赖，不复制其代码或权重 |

“免费”指不依赖收费模型 API，不表示服务器、内存、存储、运维和字体分发没有成本。OXR 条款并非普通 Apache-2.0：合并口径融资或年收入超过 200 万美元需另取书面许可，适用服务还涉及署名，因此不将其作为无条件免费商用组件。

- Paddle 识别：`PaddlePaddle/PP-OCRv6_medium_rec_onnx`，revision `50c7eacafc52fa7bcf4194e8cd08e46f8558504b`。

## 实现与交互

1. 先调用 Stirling，再检查 PPTX、页数、文字与数字。通过内容和边界检查的普通原生表格保留。
2. 对文字页按 PDFium 字符坐标重建文本框，保留字体矩阵缩放、字重和页面旋转。图形采用原页去除可重建文字后的栅格，避免复杂图表被错误拆解后拉伸。复杂表格可能变成定位文本框，而不是原生 PPT 表格，必须如实披露。
3. 原生候选如比原结果丢失更多文字/数字，立即保留原页。随后使用 LibreOffice 独立渲染原结果与候选，按相同原稿逐页比较；整体像素 MAE 增幅大于 0.001 或前景 MAE 增幅大于 0.01 时保留原页。这是筛查规则，不是视觉正确性证明。
4. 仅对有图像且可见文字不足的页面运行 PaddleOCR，包括需要重识别的不可见旧 OCR 层。低置信度、倾斜、无可见笔画或非均匀背景区域保留原图，避免擦掉图形或写入幻觉。文字替换区域使用实际墨迹边界和字体度量，减少重影和字号膨胀。
5. 可选 Unlimited OCR 2 对同一图像独立识别。字符/数字冲突、输出截断或来源哈希不符不会自动修正原图。当前一致性检查不证明阅读顺序、标点位置或语义完全正确。
6. 中文文本框显式写入东亚字体。替代字体记录在报告，缺字体度量会提示；本轮修复渲染环境里的中文缺字，未实现字体嵌入，也未保证接收端字体一致。

用户界面继续只选择转换目标，不要求选择模型；自托管处理和部分不可编辑区域有明确说明。OCR 不确定区域、图形和复杂结构仍可能是图片。所有可编辑任务返回 `needs_review`。本轮没有把实验 UI 发布到生产网站。

## 相同 200 份公开样本的前后比较

输入身份和预检分母不变：200 份，184 份可处理、合计 554 页，16 份拒绝。最终 184 份 PPTX 均重新独立打开和渲染；未用新样本替换失败项。样本主要来自上游解析器回归集，包含复杂文档、扫描/图片和异常输入，不代表客户业务文档分布。

| 指标 | 原 Stirling | 最终辅助方案 |
| --- | ---: | ---: |
| 可处理文件 / 预检拒绝 | 184 / 16 | 184 / 16 |
| 同一批非 OCR 页触发文字差异的文档 | 48 | 41 |
| 同一批非 OCR 页触发数字差异的文档 | 43 | 36 |
| 全部原始文本诊断标记（含 OCR 新增文字） | 文字 48 / 数字 43 | 文字 43 / 数字 38 |
| 保守像素筛查标记文档 | 145 | 140 |
| 每页归一化 MAE 平均值 | 0.039119 | 0.034522 |

同一非 OCR 页面比较排除了 19 个 OCR 页。新增 OCR 文字不能直接用空白或错误的旧文字层当真值，因此全文诊断与非 OCR 比较分开报告。字符计数会忽略顺序，数值 token 检查也不证明单元格对应关系；不将这些指标包装成准确率。

最终路由：116 页采用坐标修复，86 页保留原生表格，129 页因内容损失保留原结果，204 页因视觉回归保留原结果，19 页进入 Paddle OCR。19 个公开 OCR 页仅有 17 行满足当前严格的可编辑替换规则，其余低置信度/背景复杂/未检测出文字区域保留图片，没有宣称全页 OCR 成功。

按每页 MAE 差值超过 0.001 计算，88 页改善、458 页近似、8 页变差。8 个变差页全部为 OCR 替换页：原结果是原图，改成可编辑文字会有字体/位置差异。这些页仍需人工复核。对坐标修复页，门槛拦住了批量实验中发现的退化，不能据此声称所有复杂页面均已解决。

人工对比确认：目录从错误段落重排恢复为逐行目录；旋转宽表格恢复列位置且主体数字可编辑；复杂图形不再被拉伸到正文中。但字号、点线、替代字体、图内文字和少量旋转标签仍有差异。宽表格的定位文字不等于可整体操作的原生表格。

## OCR 对照与测试证据

28 个固定合成页图像分别重新运行 Paddle 和 Unlimited OCR 2。两者的字符多重集与数字 token 检查均为 28/28；这些页包括与综合件重复的单项，不是 28 个独立真实业务样本。按原 PDF 抽取字符串比较的严格顺序只有 2/28，两条路线都如此；原抽取顺序本身会把页脚放在正文前，因此不能把该数字作为人工阅读顺序准确率。此前 Unlimited 将双栏误判为表格的证据仍保留，未据此重排原生双栏文字。

本机 Mac M3 Max / 48 GB：Paddle CPU 每页中位约 2.185 秒；Unlimited MLX BF16 每页中位约 1.800 秒。二者设备、启动和工作方式不同，仅作为本机实验耗时，不是生产容量承诺。公开 OCR 页没有人工逐字真值，不报告准确率。

- **91 个自动测试通过**，当前语句覆盖率约 **82.22%**。包括旧接口/worker 测试、新坐标与旋转、字体缩放、OCR 几何/哈希校验、数字冲突、截断、无墨迹拒绝、视觉回归恢复原图片关系、缺渲染器拒绝、POSIX 取消子进程组。
- **真实联合冒烟通过**：上传 → 隔离 worker → Stirling → Paddle → Unlimited 一致性检查 → 5 个扫描文字框 → 下载授权 → 编辑/保存/重开 → 删除。另一实际文字/图形任务执行了 LibreOffice 渲染门槛，拒绝了该次较差候选。
- 旧 PDF→Word 固定 17 样本身份与 3 个测试方法，OCR 关闭/开启两种配置分别通过。没有修改旧 Word 转换逻辑或权重。
- 14 份有效合成 PDF 与 3 个预期拒绝保持；普通/合并/长表原生表格保留。全部公开输出和合成输出均独立渲染，人工重点看了目录、复杂图形、宽表格、中文、双栏与扫描正文，未声称逐页人工审核全部 554 页。
