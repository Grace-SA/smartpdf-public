## 验收范围和口径

用户确认首发覆盖常见中英文原生 PDF、报告/双栏/普通表格、清晰扫描件，包括 90° 旋转和轻微倾斜。手写、复杂公式、可编辑图表另行标明限制。公开压力集包含超出首发范围的内容，因此不能把整集比例直接当作真实客户分布的成功概率，也不能事后删除失败类型来提高成绩。

暂定上线门槛保持为：有效输入文件生成率至少 99%；常见受支持文档至少 95% 通过完整可编辑质量验收；逐页字符错误率 CER 不超过 0.1%，字符召回至少 99%，关键数字及其位置对应正确；每个文字区域边界误差不超过 2pt；还须验证结构、字体可读性、编辑/保存/重开和生产运行环境。当前质量不达标，不降低这些门槛以获得通过结果。

本轮评估按以下层次分别报告：

- **文件生成**：输出可打开、页数正确、可以独立渲染。图片保底可通过此项。
- **文字还原**：从实际 PPT 经 LibreOffice 导出的 PDF 提取文字，以源页位置绑定参考区域，计算 Levenshtein 替换/删除/插入。使用 NFKC 和去空白归一化，保留大小写、标点和数字。图片中的文字不计入可编辑文字。
- **布局精度**：合成扫描件另用已知墨迹边界与输出渲染比较。像素相似度和文字层一致均不能单独证明表格结构、阅读顺序或图表可编辑。
- **完整可编辑成功**：文字、位置、结构和独立渲染都要有证据。缺少人工参考或结构验收时保留未知，不能填成 100%。

`src/smartppt/acceptance.py` 提供独立评估器；未知值、额外文字、重复文字、错位置、数字符号、组合字符和空白页均有回归测试。

## 文字准确度：真实公开页与合成扫描分开计算

### 真实公开文档

新增数据来自 [DocLayNet 官方项目](https://github.com/DS4SD/DocLayNet)，采用 [CDLA-Permissive-1.0](https://github.com/DS4SD/DocLayNet/blob/main/LICENSE)。从 test 划分按固定哈希排序取 200 页：财报和招标各 34，其余法律、手册、专利、论文各 33。样本/原始 PDF/PNG/JSON、哈希清单和完整转换输出只保存在本机，不进入 Git。

DocLayNet 的文字单元来自自动 PDF 提取，**不是人工 OCR 真值**。先用独立 MuPDF 从源 PDF 提取文字作对照；6 份参考存在退化几何框，保留在生成分母中，但不能给出完整文字评分。其余参考与源 PDF 也并非全部一致。最终单列 **68 份源文字对照完全一致、且没有走扫描 OCR 路线的页面**作为较可靠的原生文字参考子集。这不是人工语义验收，也不是独立于本轮修复的最终留出集；这些样本已用于分析和调试，正式上线仍需另一批未参与调参的验收样本。

| 指标，68 页、130,038 个参考字符 | 本轮原始转换 | 最终转换 |
| --- | ---: | ---: |
| 字符还原得分 `max(0, 1−CER)` | 66.87% | **71.26%** |
| 正确字符召回率 | 74.11% | **76.93%** |
| 输出字符精确率 | 87.95% | **91.13%** |

最终正确字符 100,036，替换 2,368，删除 27,634，插入 7,368。字符还原得分把未恢复为文字的区域和多余文字计入错误，不能只拿输出字符精确率宣传“准确率 91%”。严格文字条件要求 CER≤0.1%、召回≥99%、所有数字区域一致且无未匹配额外字符；此处还未包含完整结构和 2pt 墨迹验收。

供诊断的全部 194 份有效参考几何页面，提供参考的一致性得分为 39.72%、字符召回 45.13%、严格文字通过 11/194；因其中参考自身与源 PDF 存在差异，不将此值称为人工真值准确率。公开真实扫描件缺少人工逐字/逐区域真值，其 OCR 准确率目前**未知**。这次实测足以否定通用上线结论，但不足以给出用户总体真实准确率。

## 本轮实现与外部依赖

1. 使用固定 revision、大小和 SHA-256 的 Paddle PP-LCNet 四方向分类模型，复用 ONNX Runtime CPU 环境；增加约 7MB 离线模型，无新增付费云 API。低置信度不旋转，检查输入/输出哈希并验证无损像素转置；三种 OCR 使用同一归正图，最后恢复原页面方向。参考 [官方方向分类说明](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/module_usage/doc_img_orientation_classification.en.md) 和 [固定模型版本](https://huggingface.co/PaddlePaddle/PP-LCNet_x1_0_doc_ori_onnx/tree/7330ab7039123e46af2dc03154b9969aa412c61d)。
2. 拉丁字体估计覆盖三种家族的常规、粗体、斜体、粗斜体。以实际 Office 输出校准字号、位置、字距；候选必须通过几何和页面比较，否则恢复原文本框。没有将未验证的中文细字重推断或字体嵌入放入结果。
3. 修复逐字符 PDF 对象被错误拆成多行的问题。只有源顺序、字体、基线、间距、缺口内容全部允许时才合并；源连续数字不能凭空插空格，真实换行/缺字不能被掩盖。先保留已验证的原始对象恢复，再在未成功页面尝试合并字符恢复，保持原质量阈值。
4. 独立位置绑定评估，单列缺失、额外、错位和数字错误；完整验收缺证据时不返回虚假的成功率。OCR 模型一致不作为评估真值。

现有 Stirling、LibreOffice、合法字体、三种 OCR 环境仍是依赖。U2/OXR 本轮实测依赖 Mac MLX；这不构成 Linux CPU/GPU 生产环境验证。OXR 继续遵循项目方此前确认的免费使用条件和既有页面引用。

## 代码审查和修复回归

本轮为本代理逐项代码复核，不声称外部审查或 CI 通过。审查后修复并增加回归：

- 上传预检不执行昂贵的原生坐标合并，放在受监督的转换 worker 内执行。
- 原生连续字符不能因排版间距被人为插入分隔符；合并不得跨越不可恢复的源对象。
- 第二阶段区域恢复失败时，保留第一阶段已保存结果及对应报告；避免输出与元数据不一致。
- 大尺寸页面限制渲染到 2400px 后，旋转中心仍使用点坐标的形状中点，不能除以渲染倍率。新增普通尺寸和 4000pt 大页面倾斜测试；这两种条件均通过。另核查批量结果全部 36 个可编辑 OCR 页面均不触发该缩放分支，最终批量指标不受此修复影响。
- 评估器不在字符片段间插入人为换行，以免破坏组合重音的 Unicode 归一化；未知结构/渲染结果保持未知。
- 字体校准保留原 XML，可逐页恢复；重复文本只按位置一对一匹配；不放宽背景擦除、文字/数字或渲染门槛。

一次测试新增断言因浮点数 `1.0000000000000284` 与 1 的边界比较失败，只增加 `1e-6` 数值余量；没有改变产品 2pt 验收门槛。先前分组优先的区域恢复实验增加了整页回退，已经撤回；最终为原对象优先。中文细字重试验未得到真实渲染支持，未保留。

## 剩余上线阻断

主要阻断仍是质量：真实密集文档恢复覆盖不足，字体/基线替换造成位置误差，中文细字重和倾斜行尚不稳定，扫描件模型分歧或擦除条件失败时保留原图。整页图片回退不能计作可编辑成功。下一阶段需围绕未恢复区域扩大可靠的局部恢复、建立独立人工校验的真实中英扫描留出集，并复验表格数字对应关系。

生产 Linux 固定镜像、合法字体交付、真实 PowerPoint/WPS 编辑、并发负载/重启/引擎临时文件清理、移动真机及准确提交的 CI 仍未完成。本地 Mac 验证不能替代这些门槛。按照用户要求暂不部署 AWS；本轮只交付可审查的功能分支改进和实测结论，不宣布通用上线。
