# M13 自建 Gotenberg 与 LibreOffice PoC 实测

日期：2026-10-28。用户授权先做PoC，收到实测结果后再确定正式开发方案。
状态：**PoC质量验证完成，正式产品未开发**。全部输入为自制合成DOCX。

## 结论

**推荐继续采用自建 Gotenberg＋原生 LibreOffice，并将受控中文字体作为必要条件。**
加入Noto Sans SC后，16份固定输入各执行两次，32份PDF共68页，均通过独立文字、
预设分页/方向、页内标记、重复表头、字形边界和重复运行一致性检查。对五类复杂
表格另做229项单元格/合并/顺序检查，全部通过。

这是样本范围内的可行性证据，不是任意Word文件保真认证或可上线产品验收。
尚未与Microsoft Word同字体导出的参考PDF逐页/字框对齐；真实合同、浮动对象、
修订、域、多栏、特殊字体及极限文档未由这16份样本证明兼容。

### 字体替代确实改变分页

默认`fc-match 'Noto Sans SC'`返回Noto Sans，实际中文回退到NotoSansCJKhk等，
并混用NotoSerif。加入字体后匹配Noto Sans SC，中文正文实际嵌入NotoSansSC-Regular/Bold。
同一100行表从3页变4页，长行从1页变2页，70段正文从3页变4页，内容没有丢失。
正式方案不能依赖默认字体回退。标题样式仍可回退到NotoSansCJKhk，字体规则还须
覆盖主题、标题、粗斜体与替代提示；不能宣传任意字体原样转换。

### 保留的失败与诊断

默认环境严格结构检查28/32通过，四次失败来自两份样本的两个重复轮次：

1. 中文标点：pypdf原始内容流序将引号抽取到行首，整段字符串校验失败；随后
   pdfplumber几何抽取和Poppler渲染显示位置正确。原始失败未改写，不直接认定丢字。
   PDF阅读器复制/搜索读序仍需产品验收。
2. 长行：默认替代字体下45段可以完整容纳在一页，预设跨页门槛失败；受控Noto
   环境为两页且内容完整。没有修改源或降低门槛让默认环境通过。

Noto环境原始严格检查32/32通过，重复运行逐字位置/字体、页文本和页尺寸签名相同。

## 独立质量核对

pdfplumber从PDF线框重新检测表格，按源预期核对横纵合并、嵌套六格、宽表96格、
100行长表及数量列、跨页长行左右列顺序和重复表头，229/229项通过。不是只确认
表中文字“在某处存在”，也不是让LibreOffice自己核验自己的输出。

两组第一轮65页均由Poppler100DPI渲染并做逐页总览检查；另查看标点、合并表、
嵌套表、跨页长行等关键单页。未观察到明显越格、遮盖或缺字框。这是作者自审与
初步渲染检查，不冒充独立人工评审或每页100%像素精审。第二轮未重复目视所有页，
而是独立比对逐字位置/字体、文本与尺寸签名。

## 输入准入缺口

| 输入         | 两环境实际返回                   | 判断                                          |
| ------------ | -------------------------------- | --------------------------------------------- |
| 0字节DOCX    | HTTP200；另次保存实际6149字节PDF | 必须在外层拒绝，不能算有效转换                |
| 截断ZIP DOCX | HTTP500；另存实际错误响应207字节 | 未生成有效PDF，但需规范错误分类，不能无限重试 |

客户端严格期待坏输入返回4xx，因此两个整批命令退出码均为1，**不把正例全部
生成成功写成整套测试通过**。500是非成功响应，不等同接受坏包；0字节200是明确
准入缺口。原始状态和响应保留。

正式服务仍须实现包结构、解压预算、宏/外部关系预检、幂等、资源与输出限制。
恶意文档、外连、取消/超时、极限大小与并发未完成专测；配置了隔离规则不等于
安全验收通过。没有正式上传API、任务队列或用户处理页面。

首次WSL会话结束引发容器正常退出，客户端连接拒绝；该尝试完整保留在
`default-fonts-transport-attempt1`。核对ExitCode0、非OOM后，保持测试期间的WSL
会话并重启同一容器，才执行上述正式计数。它是环境生命周期故障，不计作引擎
文档质量成功或失败。云部署仍须配置长期服务、重启策略和健康检查。

## 后续方案建议

PoC支持继续细化“固定引擎/字体＋独立准入网关＋有界队列＋隔离Worker＋PDF复核＋
私有结果清理”的自建路线，仍限定单份DOCX，不自动开放宏或旧DOC。
正式实现前应补Microsoft Word同字体参考、代表性授权样本、主题字体映射及
复杂域/修订/浮动对象的支持或拒绝规则。正式开发后仍需真机、安全边界、全量
累计回归及精确提交CI；本轮没有运行这些产品验收项目。

按用户要求，先交付本次实测，再确定正式开发方案；不把本机PoC称为已部署云服务。
此前本地WASM研究仍作为历史保留，未以新结果覆盖旧失败。
