# PPT 转 PDF：竞品、产品与 UI、开源技术方案

日期：2026-11-05。本文前六节保留最初 Research 决策。后续已开发为 Testing 候选，2026-11-06 原生/竞品复比发现图表保真问题，真机待验收；最新结果见 [开发与验收报告](../ppt-report.md)。未合并、未部署。

## 1. 决策与当前基线

推荐 **专用简单入口 → 本地检查 → 明确上传转换 → 真实 PDF 预览与下载**。默认每张可见幻灯片输出一页，保持原始尺寸、顺序和比例，不强制 A4、不自动裁剪、不要求打印。技术首选当前项目固定的 **Stirling PDF 3.2.2 开源核心版 + LibreOffice Impress**。

依据是当前 Word 实施记录、`src/word/WordPage.tsx`、`server/word/runner.py` 和 `config/word-core.stirling-3.2.2.json`，而不是早期 Word WASM/Gotenberg 研究结论。复用显式上传、会话、队列、阶段反馈、取消、删除、预览与下载机制；不能只把 DOCX 扩展名替换成 PPTX。

本次用户授权为调研及方案选择，遵循 requirements 15.5 的“竞品任务研究 → 开源方案与风险验证 → 产品/交互/技术方案及自查 → 开发 → 测试及独立输出 → 再对比竞品 → 交付”流程。本轮不新增功能入口、生产依赖或转换代码。当前 Excel 功能仍在修改，不将 PPT 实现混入 Excel 分支。

本轮完成官方页面与技术文档研究、现有源码核对、方案比较和验收设计。**尚未完成竞品上传任务、视觉布局观察、可点击原型和 PPT 引擎 PoC**，因此“推荐最优”指对当前项目目标的适配判断，不代表已测得转换质量或效率优于竞品。

## 2. 竞品产品与 UI 比较

| 竞品                                                          | 官方页面可核对的行为                                               | 借鉴                             | 我方取舍                                                                 |
| ------------------------------------------------------------- | ------------------------------------------------------------------ | -------------------------------- | ------------------------------------------------------------------------ |
| [iLovePDF](https://www.ilovepdf.com/powerpoint_to_pdf)        | 专用 PowerPoint 页面；选择/拖入；页面含转换、上传与处理中状态文字  | 首屏任务单一、主动作直观         | 复用大选择区和分阶段操作；页面中的状态文字不是本轮执行成功的证据         |
| [Smallpdf](https://smallpdf.com/ppt-to-pdf)                   | 选择/拖入，官方流程为上传、等待、下载；说明动画与转场不保留        | 普通文件流程短；预先解释静态输出 | 保持短流程，但按 Word 约定明确点击才上传；不复制后续签名、编辑等工具堆叠 |
| [PDF24](https://tools.pdf24.org/en/powerpoint-to-pdf)         | 专用入口；明确每张幻灯片一页；说明服务端处理、服务器位置和删除政策 | 输出语义和隐私在选择前可理解     | 写清原比例、每页一张与云端处理；不照抄它的地区/保留承诺                  |
| [Adobe](https://www.adobe.com/acrobat/online/ppt-to-pdf.html) | 选择/拖入 PPT/PPTX；入口明确 Adobe 服务器处理和登录保存条件        | 处理方式紧邻选择入口             | 使用我方已验证的服务地区/保留规则，不添加登录门槛                        |

这些是公开页面证据，不足以断言其隐藏页、备注、错误恢复、选后布局或移动端体验。没有确认闭源后台引擎；官网“保留字体/版式”的承诺不当作独立质量测量。

### 实测协议（方案冻结前完成）

用同一套自制、允许公开的 PPTX，至少完整观察 iLovePDF 与 Smallpdf；PDF24/Adobe 补充对照。记录日期、浏览器、窗口宽度、实际文案/按钮、默认行为、操作数和失败；合成输入与输出可留本地研究目录，不提交竞品界面素材作为产品资产。

任务包括：普通文件选择→执行→下载→打开；重新转换；取消选择；上传/执行中取消；损坏与伪格式恢复；连续两份文件；含隐藏页/备注的输出核对；320/390px、桌面与键盘路径。若登录/付费/反自动化阻断，记录阻断，不记为通过。私人演示文稿不上传竞品。

评价优先级：内容与输出范围正确 > 用户知晓上传及恢复方式 > 操作简洁 > 视觉密度。不能单凭首屏美观选出整体质量冠军。

## 3. UI 方案选择

| 方案                                         | 适用性                         | 主要代价                                     | 结论       |
| -------------------------------------------- | ------------------------------ | -------------------------------------------- | ---------- |
| A 选文件立即上传并转换                       | 操作最短                       | 与 Word 显式上传不一致；用户未确认就发送文件 | 不选       |
| B 先进入幻灯片编辑器/完整打印面板            | 适合编辑、讲义排版             | 普通转换增加选择、加载和误操作               | 不选为首版 |
| C 简单选择、显式转换、保留原稿、真实结果预览 | 满足直接分享 PDF；与 Word 一致 | 需清晰交代静态输出和兼容性                   | **推荐**   |

不增加转换前缩略图编辑器；读取文件自带缩略图也不能称为真实导出预览。首版无纸张、方向、DPI、主题、字体安装、幻灯片排序或多页讲义设置。PPT 本身已有页面尺寸，套用 Excel 的分页面板会增加无效操作。

### 状态与页面规格

沿用网站英文界面；以下中文为设计说明。

| 状态      | 呈现与动作                                                                                       | 行为约束                                                          |
| --------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| 空白入口  | `PowerPoint to PDF`、`Select PowerPoint file`、拖放区、云端标识；简短说明 PPTX、原比例、每页一张 | 未选文件不显示可执行转换按钮；不等待服务启动才能打开选择器        |
| 本地检查  | `Checking presentation…`；文件名、大小；更换文件                                                 | 只做有界元数据/安全检查；选择、拖入、检查都不上传                 |
| 就绪      | 文件卡片；可可靠读取时显示“共 N 张，导出 M 张可见页”；主按钮 `Upload and convert`                | 隐藏页、备注及静态输出提示紧邻主动作；不显示无法确认的计数        |
| 上传/转换 | 真实上传字节进度；准备环境、排队、转换、检查结果阶段；`Cancel`                                   | 转换无可测百分比时只显示阶段；冷启动提示沿用 Word，不承诺几秒完成 |
| 完成      | 页数、真实 PDF 预览、主按钮 `Download PDF`；次操作转换另一份、删除                               | 下载与预览同一结果字节；首屏可直接下载，不强制逐页看完            |
| 错误      | 具体原因、重试或更换文件；区分格式、受保护、容量、损坏和服务错误                                 | 原件不改；迟到结果不能覆盖取消/新文件；不自动发往第三方           |

上传说明采用当前部署实际地区及清理策略，不从历史方案复制承诺。结果预览加载失败与转换失败分开：独立输出检查通过后仍可下载。删除后确认服务器清理状态，清理未完成不显示“已彻底删除”。

桌面复用 Word 的预览容器与按钮层级，可收纳页缩略图；默认整页适配以便核对 16:9。手机单列，上方页码/翻页/缩放，下方下载；控制栏不遮挡预览、警告或错误。宽屏幻灯片不裁成竖版，允许放大和平移。320/390px、200% 缩放、长文件名、触控与键盘均验收；状态播报、错误焦点、取消后的焦点恢复和对比度沿用现有规范。

### 输出契约与提示

- 可见幻灯片按原顺序导出；隐藏页默认不导出，首版不提供包含隐藏页开关。全隐藏明确提示无可导出页面。
- 备注、批注不进入 PDF；不能仅靠移除备注页面参数就假定 PDF 注释也不存在。输出检查需搜索专用敏感标记并检查注释/附件。
- 动画与转场输出静态版，不承诺保留演示效果。动画对象最终静态可见性必须以 PowerPoint 参考导出验证，不能把逐步构建丢字都归为正常。
- 字体替代可能改变断行/字形；仅显示可确认的替代信息，无法逐文件确定时给通用检查提示，不虚构“字体完全一致”。
- 普通图片、表格、图表、形状、母版与主题是实用核心范围，必须纳入验证，不能因为没有用例就一律拒绝。SmartArt、公式、SVG/EMF 等单独记录兼容性，决定支持前保留失败分母。
- 内嵌音视频、3D、活动对象、宏等不做静默丢弃；首版遇到未支持内容给具体原因。普通静态超链接与会主动获取资源的外部关系分别判断。

## 4. 开源技术比较与推荐

| 路线                                     | 项目收益                                                                                                              | 风险/边界                                                                      | 决策                                     |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------------- |
| 固定 Stirling core + LibreOffice Impress | 可复用 Word 镜像、字体、任务及运维机制                                                                                | PPT 专项能力未测；需确认固定版的路由、过滤器、参数传递和引擎路径               | **首选 PoC**                             |
| Gotenberg + LibreOffice                  | [官方文档](https://gotenberg.dev/docs/convert-with-libreoffice/convert-to-pdf)明确覆盖 PowerPoint 与相关 PDF 导出选项 | 新增服务；同属 LibreOffice，换包装不意味着版式更好；当前文档不等于固定旧版能力 | Stirling 参数不可控时的备选              |
| 直接 LibreOffice CLI/UNO 隔离适配        | 可显式控制 Impress 导出参数                                                                                           | 自行维护隔离、启动、异常、超时、字体与回收                                     | 首选引擎内部的适配备选，先比较实际复杂度 |
| PPTX → HTML/Canvas/截图 PDF              | 容易做网页预览                                                                                                        | 需重建母版/字体/图表/形状排版；整页位图损失检索和清晰度                        | 不作为保真主线                           |
| LibreOffice WASM                         | 文档可以不出本机                                                                                                      | 项目历史 Word 实验存在内存、WebKit、清理风险；PPT 仍无验证                     | 不选当前首版                             |

当前 runner 调用 `/api/v1/convert/file/pdf`，预检及固定输入仍是 DOCX。源码还存在为指定任务强制 LibreOffice 的处理，PPT 必须核验自己的选择路径，不能假设所有格式自动走同一引擎。固定版控制器源码本轮网页获取失败，未把浮动 main 的实现当成 v3.2.2 事实。

[LibreOffice PDF 参数](https://help.libreoffice.org/latest/en-US/text/shared/guide/pdf_params.html)列出隐藏幻灯片、备注页、备注、原稿嵌入等独立选项。PoC 目标显式控制 `ExportHiddenSlides=false`、`ExportNotes=false`、`ExportNotesPages=false`、`ExportOnlyNotesPages=false`、`IsAddStream=false`，并禁用 PDF 转场。该文档是当前上游参考，须在项目镜像内确认有效性；Stirling REST 是否能完整传递参数尚未证明。不得将文档默认值视为生产保证。范围/页码选项不对用户开放，避免源幻灯片号与 PDF 页码混淆。

许可以 [v3.2.2 LICENSE](https://raw.githubusercontent.com/Stirling-Tools/Stirling-PDF/v3.2.2/LICENSE)及项目固定核心物料为基线。根 MIT 有目录例外，不将完整发行包笼统称为 MIT；保留 LibreOffice、字体、基础镜像与第三方通知。不导入受限模块、不复制本机商业字体、不因升级 PPT 引擎替换 Word 已验证镜像。

### 适配与安全边界

新增独立 PPTX 预检器和任务类型，复用任务基础设施；不放宽 DOCX/XLSX 策略。校验真实 OOXML 内容类型、演示清单、页面 ID/关系、母版/版式/主题、图片及图表依赖；隐藏标志按规范解析且跨包关系核对，不仅扫描扩展名。图表内嵌的标准 XLSX 缓存数据与任意 OLE/附件要区分：允许前者前须递归限制和验证，不一律当成可执行对象，也不能无检查放行。

ZIP/XML 路径、重复条目、CRC、展开字节、深度/节点、资源数量与图片解码像素设有界预算；拒绝实体、宏、加密/密码、签名、ActiveX/OLE、远程图片/模板和外部数据刷新。未知关系给明确原因，普通 HTTP/HTTPS/mailto 静态链接按已审阅策略保留。引擎仍禁出站、禁止宏执行，上传匿名文件名；单任务容器、限流/队列/取消/超时和文件清理复用 Word 后重新验证。

拟定单个 `.pptx`，输入/输出各 30 MiB、最多 200 个输出页，另设总源幻灯片/隐藏页及资源预算防止绕过。以上为初始实验预算，容量测试后冻结，不先做产品承诺。`.ppt` 竞品常支持，但为旧二进制格式，首版不直接沿用 PPTX 检查器；先做独立安全与质量实验再决定。`.pptm/.pps/.ppsx/.odp` 等不自动开放。UI 用“PowerPoint”作为工具名，接受格式如实标为 PPTX。

## 5. 验证矩阵与进入开发的门槛

冻结至少 24 份独立编写的合成 PPTX，清单保留输入哈希、预期可见页数/尺寸/文字/图片、参数及参考输出。覆盖 16:9、4:3、自定义尺寸、中文/英文混排、换行/溢出、母版/主题、表格、透明图片/裁剪、层叠/旋转/渐变、常见图表及内嵌数据、SmartArt/公式/矢量诊断、动画构建、隐藏页/全隐藏、备注/批注、普通链接，以及容量和危险输入。诊断样本与承诺支持样本分开，不删除失败样本改善分数。

| ID   | 验收内容                                                                                                                     |
| ---- | ---------------------------------------------------------------------------------------------------------------------------- |
| P-P1 | 选择/拖入/更换/取消选择不上传；明确点击才上传；主动作与 Word 一致                                                            |
| P-P2 | 按预期可见页数和顺序输出；原尺寸比例正确；无隐藏页、备注、批注、原稿附件泄漏                                                 |
| P-Q1 | 与 Microsoft PowerPoint 实际导出的参考 PDF 逐页比较；若环境无 PowerPoint 明确标未验证，不能仅以同一 LibreOffice 输出自证兼容 |
| P-Q2 | 独立 PDF 解析 + 文本抽取 + 渲染/目视；检查缺字、截字、重叠、图表数值/图例、图片裁切、背景/母版和页面边界                     |
| P-Q3 | 文字保持可搜索/选择；不将整页截图作为降级成功；预览与下载内容一致                                                            |
| P-S1 | 损坏、伪格式、炸弹、宏、外链、危险内嵌数据拒绝；真实禁网、会话隔离及不记录内容                                               |
| P-L1 | 启动/队列/转换各阶段取消、重复任务、过期、删除、超时/崩溃；容器和输入/输出不残留、迟到响应不复活                             |
| P-U1 | 两款竞品完整任务对照及产品自查；320/390px/桌面、键盘/读屏、真实手机选择/预览/下载                                            |
| P-R1 | 单元/集成/边界及所有已验收工具累计回归；共享服务公平排队，PPT 不使 Word/Excel 饥饿                                           |

先在本地固定镜像跑核心 PoC，证明可见页、隐藏/备注安全、原尺寸、图表/母版和实际参数可控，测冷启动/暖启动、转换耗时与峰值资源。若接口不能满足，拿同一输入比较受控 CLI/UNO 或 Gotenberg，再冻结适配路线。PPT 成绩单独记录，不能复用 Word 页数/耗时当成通过。

## 6. 设计自查与交付顺序

已自查：无文件不出现多余执行动作；不自动上传；不引入编辑器；原比例无需用户配置；隐藏页/备注策略明确；手机不强制横屏；错误有恢复路径；不虚构质量/进度/字体检测；常见图表图片不因缺测试被一律排除。

待完成：竞品真实操作与截图目视、可点击原型、固定镜像 PoC、参考输出与容量测量。当前仍是 Research，不标为 Design frozen 或 Testing。

1. 补齐竞品完整任务及关键技术实验，更新证据与失败项。
2. 根据结果冻结支持矩阵、UI 原型、导出参数、资源预算和技术适配；完成设计自查。
3. 按单功能规则，在独立功能分支开发，逐项测试、累计回归、独立输出检查和实现后竞品复比。
4. 交付可运行候选、测试证据、已知限制及真机未验证项。提交/推送前保留仓库资产检查及 hooks；按 AGENTS 通过 origin 同步并核对三端分支对象。
5. 合并及生产发布遵守各自授权和精确提交 CI；本调研不构成上线许可。

## 2026-11-05 实施更新

用户随后授权继续开发。已选择方案 C，并在独立功能分支实现 PPTX 入口、任务与预览/下载链路。技术采用独立固定 Stirling 开源核心容器中的 LibreOffice Impress UNO 适配，显式控制隐藏页/备注/原稿嵌入；未启动 Java HTTP 包装器，未改 Word/Excel 的镜像 pin。详情、失败历史和未完成门槛见 [本地开发报告](../ppt-report.md)。当前为 Testing，不表示竞品完整任务、原生 PowerPoint 保真、真实手机或生产验收已通过。

## 2026-11-06 验收更新

已完成 24 份固定样本/27 页的 Microsoft PowerPoint 原生参考导出与逐页对照，以及 iLovePDF/Smallpdf 的普通下载、坏输入、离开上传、重做和窄屏任务。原生对照确认基础输出范围和尺寸正确，但柱/条图默认颜色、自动坐标轴与散点标记存在视觉差异，不能按完全保真验收。竞品标准样本中，iLovePDF 排除隐藏页，Smallpdf 包含隐藏页。保持明确上传与仅可见页的产品选择；保留图表质量问题，真机待条件具备后继续。结果和证据边界以开发与验收报告为准。
