# Word 转 PDF 正式产品与技术方案

日期：2026-10-28。阶段：研究与设计完成，待评审；尚未实施产品功能、创建云资源或发布。

## 产品决策

采用自建 Gotenberg + 原生 LibreOffice，首版定位为单份 DOCX 的云端转换与结果预览。
固定引擎、字体和转换参数，明确提示版式可能变化，不宣传与 Microsoft Word 完全一致。
本方案替代早期浏览器 WASM 方案作为后续实施基线；历史研究保留，不覆盖失败记录。

[Word 参考实测](m13-word-reference-results.md)已覆盖 16 份固定合成 DOCX、34 页 Word 输出。
固定 Noto 环境的页数和合成标记所在页全部匹配；默认字体有 3 份页数不匹配。
实测支持该技术方向，但不足以推广到任意用户文档、罕见字或精密印刷版式。

继续复用此前[竞品与开源研究](../m13-report.md)的选择文件、显式开始、状态反馈、预览、下载流程。
云端版本必须在上传前解释文件将离开设备；原有本地工具保持原契约，站点的“无上传”文案须限定到本地工具。

## 首版用户流程

1. 工具页常驻“云端转换”标识，说明单份 DOCX、30 MiB 上限、字体可能替代、文件处理地区和删除时限。
2. 选择或拖入文件后先展示名称和大小；本地只做扩展名、大小和明显空文件检查。取消选择不上传。
3. 用户主动点击“上传并转换”才发送文件。按钮旁完整显示上传说明，不预勾选同意、不静默切换第三方。
4. 展示“上传中 / 检查文件 / 等待处理 / 转换中 / 检查结果”。上传进度可精确显示；转换阶段不编造百分比。
5. 服务端预检发现字体替代或支持范围内的复杂版式时暂停，列出具体问题，让用户选择继续或取消。
   硬拒绝项目不能通过“继续”绕过。普通文档无需额外弹窗。
6. 成功后显示页数、可浏览的 PDF 预览、字体提示及“请核对分页与表格”，提供下载和立即删除。
   预览失败但已验证 PDF 可下载时分别说明预览状态；转换失败不出现假成功下载。
7. 取消会终止任务并触发清理；重新转换须显式操作。失败显示可理解的原因、可行修正方法和匿名错误编号。

键盘与屏幕阅读器可完成上述流程。替换文件会结束旧任务；刷新可恢复同一浏览器会话的未过期任务。
过期状态清楚说明文件已不可下载。首版无批量、云盘导入、链接抓取、OCR、格式编辑或付费订阅。

## 字体基线

正式候选使用本次通过验证的 Noto 环境。固定的是完整镜像内的字体集合及配置，不是仅安装一个同名字体。

| 项目                         | 固定值或规则                                                                                  |
| ---------------------------- | --------------------------------------------------------------------------------------------- |
| 官方基础镜像                 | `gotenberg/gotenberg@sha256:13672f317b443c793e972b1bd2155ec62a3e7b6891b411e8196442cc053ee5f5` |
| 实测版本                     | Gotenberg 8.39.0；LibreOffice 26.8.1.1 680(Build:1)                                           |
| 实测派生镜像配置 ID          | `sha256:9d5a997c025000070cd60bdfb6931ba6bb3adaaf49c1ff16d66efb9f9db5512f`                     |
| 实测派生镜像 manifest digest | `sha256:d9401163a3edc31241d37ac3644791aacd3c64142febbda41e3cd52926e10aa3`                     |
| 新增中文字体                 | 仓库既有 `NotoSansSC-variable.ttf`，Version 2.004-H2；OFL 1.1                                 |
| 字体 SHA-256                 | `a3041811a78c361b1de50f953c805e0244951c21c5bd412f7232ef0d899af0da`                            |
| 正文命中                     | `Noto Sans SC` 实测匹配新增字体，PDF 中出现 Regular/Bold；不把主题标题也称为已命中            |
| 西文字体及回退               | 保留上述镜像中的 Liberation、Carlito、Noto 和 DejaVu 及现有 fontconfig；不在运行中安装或更新  |

交付镜像时生成每个字体文件的哈希、家族/字重、许可和 `fc-match` 解析表，连同 fontconfig、镜像 digest 入库锁定。
镜像升级、字体变化、转换选项变化都必须重新跑固定样本与 Word 对照，禁止使用浮动 `latest` 标签发布。
本地镜像配置 ID 与 registry manifest digest 是不同标识；不能混用。

字体预检需要解析正文、样式继承、表格、页眉页脚、编号及 theme 的 ascii/hAnsi/eastAsia/cs 字体。
从有效字体请求解析到镜像中的实际家族；不能只扫描 `fontTable.xml` 或 `w:rFonts` 的直接声明。
主题解析不完整、发生回退或缺字覆盖风险时必须显示提示，不宣称已精确匹配。
未知字体默认暂停，展示请求名与可确定的替代名；无法确定替代名时如实说明。
首版不接收自定义字体，不使用用户文档中的嵌入字体，也不分发 Windows 商业字体。

不强制改写用户 DOCX 为 Noto，否则会改变原文档的字体语义。请求已安装字体时按原样转换，缺失时使用固定回退并提示。
当前 Word 参考采用本机实际字体，PDF 记录有 Arial、Calibri、Cambria、MS Gothic、Microsoft YaHei；
它与容器不是同字体实验。Windows 同名 Noto 文件与仓库文件哈希不同，因此本轮结论只覆盖“本机 Word 实际输出对照”。
需要精密 Word 版式的用户应使用原 Microsoft Word 导出；首版不承接此承诺。

## 支持与拒绝范围

“支持”指在限定文件与字体规则内提供转换和预览，不意味着所有文档与 Word 像素相同。

| 内容                                                                           | 首版处理                   | 依据与边界                                                         |
| ------------------------------------------------------------------------------ | -------------------------- | ------------------------------------------------------------------ |
| 普通中英文正文、常见标点、9–24 磅及粗体                                        | 支持                       | 合成样本已对照；罕见字、其他文字方向未覆盖                         |
| 显式分页、自动分页、A4 横竖分节、独立页眉页脚                                  | 支持并提示核对             | 当前样本页数及标记页一致；没有证明任意布局都相同                   |
| 内嵌 PNG/JPEG 与普通表格                                                       | 支持                       | 图片样本位置/可见内容已检查；不由 PDF 图片对象数推断内容丢失       |
| 横纵合并、单层嵌套、重复表头、长表与可拆分行                                   | 支持，预检列为复杂表格提示 | 合成验证已覆盖；高度和边框仍可能变化，结果须预览                   |
| 字体缺失或字体主题回退                                                         | 暂停并提示，用户可继续     | 不静默宣称原字体保真；存在缺字则拒绝发布结果                       |
| 浮动图片、文本框、艺术字、SmartArt、图表、公式、竖排、分栏、脚注尾注、连续分节 | 首版拒绝                   | 尚未完成相应 Word 样本验收；可在以后单独扩展                       |
| 修订、批注、隐藏文字、数据绑定内容控件、表单控件                               | 首版拒绝                   | 避免隐式接受修订、暴露隐藏内容或改变显示语义                       |
| 宏、ActiveX、OLE、嵌入附件、嵌入字体、altChunk、包签名                         | 拒绝                       | 不执行、不展开、不静默移除后转成“成功”                             |
| 外链图片/模板/对象、外部数据与主动域                                           | 拒绝                       | 普通超链接作为文字保留，不自动访问；仅超链接关系可带提示继续       |
| 任何复杂域或简单域，包括页码/日期/目录                                         | 首版统一拒绝               | 当前样本页眉页脚是静态文字，未验证域更新语义；不偷偷刷新或采用缓存 |
| DOC、DOCM、DOTX、ODT、RTF、加密或需密码的文件                                  | 拒绝                       | 引擎支持其他格式不扩大产品契约                                     |
| 多文件、空包、损坏包、超限、无可见正文/图片/表格                               | 拒绝                       | 图片文档、静态页眉与正文规则需分别判断；不靠文本字符数判断空白     |

不认识的影响显示或安全的 OOXML 构造采用拒绝或明确的未支持错误；不能忽略未知节点后标记“已通过预检”。
预检是支持策略检查，不能证明任意文件无恶意或与 Word 一致，隔离层仍然必需。

## 服务端输入预检

建议以下版本化预算作为实现起点，均需边界测试后才能上线：单文件 30 MiB，最多 2,048 个 ZIP 条目，
总解压 150 MiB，单 XML 20 MiB，单条目压缩比 100:1，XML 深度 128，预检墙钟 5 秒。
图片只接收嵌入 PNG/JPEG，单图 40 MP、总计 100 MP；超过任一预算给出明确超限原因。
这些是防资源耗尽的工程限制，不是本轮测得的容量。

先限流及流式计数，再检查文件签名与真实 ZIP/OPC 结构；不能信任文件名、浏览器 MIME 或 ZIP 中声明的大小。
检查中央目录与本地条目一致、CRC、压缩算法、重复/归一化冲突路径、绝对路径、盘符、反斜杠、`..`、符号链接、
多卷/加密包及多余尾部载荷；读取过程持续执行实际解压预算。禁止将文件先任意解压到宿主机再验证。

安全 XML 解析禁用 DTD、外部实体和网络访问。核对 `[Content_Types].xml`、根关系和唯一 Word 主文档，
拒绝伪装的宏 content type、恶意关系和上述未支持结构；遍历所有可达部件，检测未声明或冲突部件。
页面数不得采用 DOCX 属性的缓存值；仅在隔离转换后以独立 PDF 解析器判定 200 页上限。
输出 30 MiB 上限也须在响应流中执行，不等待完整结果落盘后才限量。

PoC 中零字节 DOCX 得到 HTTP 200 PDF，截断 ZIP 得到 HTTP 500。因此“引擎返回 200”不能替代预检，
也不能把所有 500 都当作瞬时故障重试。坏输入固定拒绝；资源或传输故障只允许有限重试。

## 技术架构

现有 React 静态前端 → 同源任务 API → 私有 S3 上传区 → 预检 Worker → SQS → 转换 Worker →
私有 Gotenberg → 独立 PDF 复核 → 私有 S3 结果区 → 授权预览/下载。
前端只对接产品 API，不公开 Gotenberg，不透传任意转换参数、URL、webhook 或 PDF 引擎操作。

初期使用独立 Linux 主机上的一个转换执行单元，2 vCPU / 4 GiB 是压测起点。
每个 LibreOffice 实例最多一个活跃转换，外层全局等待队列建议上限 20，满载返回可重试的忙碌状态；
扩容增加隔离实例。API 可独立部署；无需为首版引入 Kubernetes。

首版实现选型固定为：沿用 React/TypeScript 前端，CloudFront 同源 `/api` 转发到 API Gateway HTTP API +
Node.js/TypeScript Lambda；DynamoDB 保存短期任务状态、租约及幂等记录，SQS Standard 传递任务，S3 保存私有对象。
独立 EC2 Linux 上的 Node.js Worker 负责预检与调度 Docker，转换执行单元仍为上述固定 Gotenberg 镜像。
宿主机初始容量按至少 4 vCPU / 8 GiB 留出系统、Worker 与复核进程余量，最终规格由目标云压测确定。
首版单实例允许计划维护时短暂不可用；扩为双 Worker 仍沿用相同任务协议，不将单机称为高可用。
队列准入配额以 DynamoDB 条件更新控制并由清理任务回收失效占位，不以 SQS 近似队列长度作严格上限。
DynamoDB TTL 只作元数据过期兜底，不能替代及时撤销权限或删除 S3 文件。

API Gateway 仅承载小型控制请求。上传直接到受限 S3 对象；30 MiB PDF 与 Range 预览经 CloudFront 的
`/files/*` 路径转发 ALB 和独立 Node.js 下载进程，以流方式交付，避免将大文件塞进控制 API。
下载进程每次请求核验任务归属、状态与到期时间，不暴露转换路由；与有界转换执行进程分别限流。
匿名用户使用随机会话与任务归属记录，Secure/HttpOnly/SameSite Cookie、同源请求校验及 CSRF 防护；
任务 ID 本身不是访问凭据，跨会话访问统一拒绝。限流与配额同时覆盖建单、上传完成、轮询和结果读取。
[Gotenberg 配置](https://gotenberg.dev/docs/configuration)与[Office 路由](https://gotenberg.dev/docs/convert-with-libreoffice/convert-to-pdf)是底层接口依据。

转换容器无云凭据、无宿主文档目录、非 root、最小权限、只读根文件系统、受限临时盘与进程/CPU/内存。
Worker 用独立最小权限角色读写指定对象；通过专用通道把文件送入转换容器。
转换容器在网络层禁止出站，另启用 LibreOffice deny-list `.*`、禁止 downloadFrom、禁用 Chromium 和无关路由；
应用配置不能替代网络隔离。对 URL 及外部内容的限制须在锁定版本上实际验证。
[官方出站规则](https://gotenberg.dev/docs/outbound-url-filtering)的默认策略较宽，不能照默认暴露公网。

转换超时建议 90 秒，等待超过 5 分钟返回忙碌失败；含上传的任务总寿命最多 10 分钟。
超时或卡死直接回收该执行单元和临时目录；取消不能只停止轮询而让后台无限执行。
每个任务独立临时空间，完成后清理并在租户之间回收执行环境，防止文档残留。
预检/解析也在受限进程中运行，受时间和内存约束。

## 任务协议与数据生命周期

| 接口                             | 语义                                                               |
| -------------------------------- | ------------------------------------------------------------------ |
| `POST /api/word-pdf/jobs`        | 校验会话、限额、大小，返回任务 ID 与限时上传授权；幂等键防重复建单 |
| `POST /jobs/:id/upload-complete` | 核对对象真实大小、校验和、版本；进入预检；客户端不可自报预检通过   |
| `GET /jobs/:id`                  | 返回状态、过期时间、支持/字体提示；无原始文档内容与存储路径        |
| `POST /jobs/:id/continue`        | 仅对当前版本提示作确认；文件/字体 profile 变化使旧确认失效         |
| `POST /jobs/:id/cancel`          | 标记取消、阻止发布，终止执行或丢弃迟到结果并清理                   |
| `GET /jobs/:id/result`           | 成功且未过期时签发短时、仅该对象的预览/下载授权                    |
| `DELETE /jobs/:id`               | 立即撤销产品访问并触发清理；状态可查询，重复请求幂等               |

状态：`created → uploading → preflight → needs_confirmation/queued → converting → validating → succeeded`；
任意非终态可到 `cancelled/failed/expired`。状态更新使用版本条件、Worker 租约和 fencing token，
SQS 重复消息不得重复发布。只允许一次可归因的瞬时故障重试；确定性拒绝不重试。
取消/过期与完成并发时优先撤销结果访问；完成消息不能让已撤销任务复活。

地区建议澳大利亚悉尼，正式部署前确认产品处理地区。全部对象私有、传输加密；文件名仅在浏览器展示，服务端使用随机对象键。
上传授权 5 分钟；结果授权建议 60 秒且不超过任务到期时间，下载/预览由可撤销网关控制，避免已签 URL 在删除后仍可访问。
任务结束起保留最多 1 小时，立即删除提供更早清理。5 分钟清理任务负责应用删除，S3 生命周期作为兜底，不能将生命周期规则称为实时删除。
输入、结果、预览、失败残留、对象版本和未完成分片都属于清理范围；不进入长期备份和业务日志。
任务状态只保留无内容的短期诊断计数；技术错误日志不得含文件名、文本、密码、下载地址或原始引擎响应。
首版不转发任何第三方转换商；若以后更换供应商，须重新明确用户的数据流和授权。

## 输出复核与验收

输出必须能由独立解析器打开、未加密、1–200 页、文件大小合规、页框合理，不含脚本/启动动作/附件。
保留可搜索文本，不用整页截图冒充转换；图片文档本身无文本时不承诺 OCR。
对预检提取的可见文本和 PDF 内容做可解释的规范化核对；不能将修订/隐藏文字纳入普通正文，
不能忽略金额、字符缺失、顺序异常。无法确定内容完整性时显示验证失败，不交付假成功。
PDF 可解析不等于视觉正确，最终预览与固定样本逐页审核仍是验收条件。

实现完成后必须通过：

- 原有 16 个源哈希不变；固定字体重复转换、全部结构检查、229 项表格检查及 34 页 Word 对比不退化。
  合成标记完整且所属页一致，图片可见、表头重复正确，无缺字/裁切/重叠；位置变化单列，不用总相似度掩盖局部缺陷。
- 预检的空文件/损坏包/伪装包、ZIP/XML/图片边界、支持与拒绝矩阵的每个类别都有固定用例。
- 30 MiB、200 页、超时、取消竞态、队列满、重复消息、Worker 崩溃、重试、跨会话访问及清理故障验证。
- 在目标云配置测峰值内存、磁盘、并发、冷启动与删除时限，确定容量和成本；本机约 0.2 秒中位数不作 SLA。
- 完成桌面和手机上传、断网/刷新恢复、可访问性、预览下载及删除实机验收，重比竞品关键流程。
- 全站累计回归、独立输出检查与提交对应 CI 通过后才能准备验收构建；生产发布仍需明确授权。

本轮只完成研究脚本、参考输出、逐页检查与方案自审，不将这些准入条件写成已执行的产品测试。
