# Excel 转 PDF：竞品、产品与 UI 选型

日期：2026-11-04。状态：Research / 推荐设计基线；未实施转换功能，未部署。

## 1. 结论与 Word 基线

推荐“简单选择入口 + 工作表选择 + 保留原打印设置 + 实际 PDF 预览 + 按需调整分页”。技术优先复用现有 **Stirling PDF 3.2.2 开源核心版 + LibreOffice**，而不是另建一套 Office 服务。

基线以当前源码 `379a8db`、[Stirling 实施记录](../m13-stirling-implementation.md)、`server/word/runner.py`、`config/word-core.stirling-3.2.2.json` 为准。10 月 28 日 Gotenberg 文档是历史研究；11 月 2 日用户已改选 Stirling，11 月 3 日 Word UI 采用分阶段单一主动作。不能把旧 Gotenberg 计划写成当前实现。

复用 Word 的文件选择、显式上传、阶段反馈、预览、下载、取消、删除、匿名会话与隔离转换机制。Excel 新增的是工作簿预检、工作表范围、打印设置、公式语义和分页验收，不能只替换扩展名。

本轮完成官方公开页面及文档比较、当前项目实现核对和产品设计。没有对竞品上传合成工作簿并跑完整任务，没有运行 Excel 引擎 PoC，没有实测手机或作性能排名。因此推荐代表对当前项目的适配判断，不代表已证实竞品转换质量优劣；按需求 15.5，实施前仍需完整竞品任务和关键技术实验。

闭源竞品的后台引擎均未确认。本轮读取网页内容可核对入口文字与产品说明，不能代替颜色、实际按钮位置、手机布局或上传后操作的目视验收。

## 3. UI 方案比较与推荐

| 方案 | 操作负担 | 分页可控性 | 与现有 Word 一致性 | 判断 |
| --- | --- | --- | --- | --- |
| A 选文件后直接自动转换 | 最低 | 低，容易到下载后才发现分列/小字 | 低，改变显式上传约定 | 不选 |
| B 首屏完整打印设置面板 | 高，用户选文件前无法判断设置 | 高，但容易误改原稿 | 中 | 不选为默认流程 |
| C 分阶段转换，设置收纳，真实预览后调整 | 普通文件短流程；问题文件才增加操作 | 高，可核对并重生成 | 高 | **推荐** |

选择 C 是工程与 UX 判断，尚无用户研究数据或点击耗时实验。主要成功标准是用户能确定“导出了哪些表、内容是否完整、分页是否可读”。

### 3.1 页面与主操作

**初始页**：标题“Excel 转 PDF”，副标题“将工作表转换为便于打印和分享的 PDF”；云端标识；大拖放区和“选择 Excel 文件”。下方说明单个 `.xlsx`、拟定 30 MiB、文件会上传服务器、版式可能变化。没有文件时不展示可点击的转换按钮。保留 Word 已有视觉组件和移动端选择器行为。

**选择后**：展示文件名、大小和“更换文件”；本地有界解析只读取工作表名称、可见状态、打印设置信息，不在浏览器重算公式或声称生成真实分页预览。工作表复选列表保持原顺序；默认选择所有可见表；隐藏/veryHidden 表不可选择，只提示隐藏表数量。未选表时主按钮禁用并解释。无可见表、解析失败时给出明确原因。

首次展开区只展示“工作表”和“版式：保留原打印设置”。“更多页面设置”收纳方向、纸张和缩放；默认全部保留原设置。主按钮“上传并生成 PDF”，旁边沿用 Word 的真实处理地区与文件保留说明。选择、拖入、修改设置都不上传；点击主按钮才上传。服务端重新核验，不能信任前端表单。

**处理中**：上传中显示真实字节进度；检查文件、准备转换环境、排队、生成 PDF、检查结果显示阶段，不编造百分比。沿用当前 Word 冷启动提示，不能许诺“几秒完成”。取消在各阶段有效。

**结果页**：桌面左侧工作表目录/缩略图，中间实际 PDF，右侧收纳的页面设置；显示页数和所选工作表。主操作“下载 PDF”，次操作“调整分页”，并保留立即删除与转换其他文件。若无法可靠建立工作表到 PDF 页码映射，只展示选中表清单与 PDF 页码，不能猜测每表页数。

首次结果默认沿用原稿。用户点“调整分页”后进入调整态，主操作变为“更新 PDF”；设置改变时旧预览明显标记“尚未应用”，旧下载入口禁用。新结果通过检查后再切换为“下载 PDF”。异步结果必须绑定设置版本，迟到响应不得覆盖最新设置或取消状态。

**手机**：采用“工作表与设置 → 预览”两步，上下排列，不压缩成三栏；预览顶部显示当前页/总页数、缩放与上一页/下一页；底部仅一个常驻主按钮。设置返回后保留选择和滚动位置；按钮不遮挡警告。工作表名称可换行，复选项整行可点；键盘焦点、错误摘要、状态播报和触控尺寸沿用项目规范并实际验收。

### 3.2 设置语义

| 设置 | 默认 | 可选项与边界 |
| --- | --- | --- |
| 工作表 | 全部可见表 | 勾选子集，顺序固定为原顺序；首版不提供隐藏表导出或自由重排 |
| 输出 | 一个 PDF | 选中表依原顺序输出；首版无每表 ZIP 或批量工作簿 |
| 打印范围 | 保留原打印区域 | 未设置时采用引擎正常打印范围并预览；首版不提供手输 A1 范围或一键忽略原打印区域 |
| 纸张 | 保留每表设置 | 可统一 A4/Letter；不自动覆盖混合纸张 |
| 方向 | 保留每表设置 | 纵向/横向；不以“自动”暗中改写 |
| 缩放 | 保留每表设置 | 所有列适合页宽（纵向可多页）；整张表适合一页（需可读性提醒） |
| 网格线、重复表头、页边距、页眉页脚 | 保留原设置 | 首版无高级编辑；网格线与用户设置的单元格边框不同 |

新增统一设置仅作用于选中表的临时转换副本，不修改源文件。先做技术验证再开放控件；暂未实现的设置不摆放可点击占位按钮。

**禁止直接把 `SinglePageSheets=true` 接到“整张表适合一页”。** [LibreOffice 官方说明](https://help.libreoffice.org/latest/en-US/text/shared/guide/pdf_params.html)指出该参数忽略纸张、打印范围和显示/隐藏状态，可能将隐藏表输出。我们需要的是受控纸张内的打印缩放，且严格保留所选范围。

### 3.3 提示与恢复

- 字体替代：列出可确定的替代关系，提示检查中文、金额和表头；缺字不能标为无损成功。
- 宽表多页：提示“部分列分布在多页，可尝试横向或所有列适合页宽”，不自动裁列。
- 一页缩放：只有实际估算出有效字号/比例才显示具体值；否则提示放大核对，不能伪造“字号过小已检测”。
- 打印区域：明显说明“按原文件打印区域导出，区域外内容不会包含”，不把这种预期省略误报为全部内容保留。
- 空白或超页数：允许取消、回设置或更换文件；不静默删除所有看似空白页，空白页可能来自原分页。
- 预览失败：仅在独立输出检查通过时允许下载，并区分预览失败和转换失败。
- 替换文件、离开、刷新恢复、取消、过期和删除确认复用 Word 语义；执行中取消后不得发布迟到结果。

## 4. 开源技术选型

| 路线 | 与当前工程的关系 | 主要边界 | 结论 |
| --- | --- | --- | --- |
| Stirling 3.2.2 core + LibreOffice | 已有固定核心镜像、接口、字体、隔离、清理及 Word UI | Excel 仍需预检与分页控制；每任务启动有明显延迟 | **首选**，先验证普通导出和设置实现 |
| Gotenberg + LibreOffice | 已有历史 Word PoC；官方支持 Excel | 再引入服务且仍是 Calc 兼容性；REST 参数不等于完整每表打印控制 | 备选，不并行建设生产后端 |
| 直接 LibreOffice UNO Worker | 可访问每表页面样式和导出选择 | 需自行维护加载、隔离、超时、字体与回收 | 若现接口不足，作为同引擎受控适配方案 |
| SheetJS/ExcelJS + HTML/Canvas/PDF 排版 | 前端可解析数据 | 不能由读写工作簿能力推断具备 Excel 打印、公式和图表保真 | 不选为转换主引擎；metadata 解析另行选型 |

当前服务调用 `/api/v1/convert/file/pdf`，上传字段 `fileInput`，Word runner 固定输入 DOCX。不能声称当前接口已经支持工作表选择、每表缩放或 Excel 安全预检。

上游浮动 `main` 的 [OfficeToPdfService](https://raw.githubusercontent.com/Stirling-Tools/Stirling-PDF/main/app/core/src/main/java/stirling/software/SPDF/service/OfficeToPdfService.java)另有 Java Office 转换和 LibreOffice 回退。它仅作为演进观察，不代表项目锁定 3.2.2 核心实际使用该引擎。本轮未获取新的固定提交，不据此升级或复制代码。

许可沿用项目已核对的固定核心发行物和清单。[v3.2.2 根许可](https://raw.githubusercontent.com/Stirling-Tools/Stirling-PDF/v3.2.2/LICENSE)明确列出目录例外；不能概括为“完整 Stirling 镜像都可按 MIT 商用”。保留核心、基础镜像、LibreOffice、字体与第三方组件各自通知；不引入受限附加模块。

[Gotenberg Office 文档](https://gotenberg.dev/docs/convert-with-libreoffice/convert-to-pdf)可验证其 LibreOffice 路线；其 `singlePageSheets` 具有同样的隐藏表问题，换包装器不会解决语义错误。

### 4.1 适配边界

建议在现有任务管理之下添加独立 `excel-pdf` 任务类型和 Excel 预检器；共享会话、限流、队列和下载校验，分离 DOCX/XLSX 支持策略。保留 Word 固定镜像和原转换路径，Excel 候选升级不得直接替换 Word 已验证引擎。

先验证 Stirling 固定版是否能接受必要的受控设置。若不能，优先评估临时 XLSX 中定点变更打印相关 OOXML，保持公式、共享字符串、绘图及关系原样；或用 LibreOffice UNO 操作隔离实例。两者都需独立输出验证，不预先认定 XML 改写最安全或最省工。

工作表选择不能通过删除未选工作表实现，跨表公式可能引用它们。保留依赖表供计算，导出选择与工作簿内容分开；隐藏其他表是否足以限制导出也须实验，不作为已证实机制。UNO 候选可研究 [TablePageStyle](https://api.libreoffice.org/docs/idl/ref/servicecom_1_1sun_1_1star_1_1sheet_1_1TablePageStyle.html) 的 `ScaleToPagesX/Y` 和页样式；共享页样式需按表克隆，避免修改一表影响其他表。

### 4.2 公式与内容契约

Excel 转 PDF 输出显示结果而非可编辑公式。LibreOffice 的[加载重算策略](https://help.libreoffice.org/latest/en-US/text/shared/optionen/01060900.html)可影响结果，不能保证“不重算就忠于原稿”或“重算一定与 Excel 相同”。首版建议仅接受通过固定测试的常用内部公式；缓存、跨表引用、1900/1904 日期、精度、错误值和格式均要核对。

PoC 明确比较加载前缓存与转换显示值，并记录是否发生重算。缺失缓存、无法识别的公式、易变函数或不确定语义给出未支持错误；不自动填零，不静默将 `#NAME?` 当作成功。外链数据、宏、DDE、数据连接和刷新默认拒绝；不访问外部来源。安全禁网和宏禁用必须在引擎层实际验证。

## 5. 建议首版范围与验收

首版单个 `.xlsx`，普通中英表格、数字/货币/百分比/日期格式、边框填充、合并格、换行、隐藏行列、原打印区域和已验证的常用内部公式。图表、条件格式、图片、筛选结果、重复表头和复杂分页必须纳入 PoC；未验证通过的项目明确标为不支持，不能把 Word 样本成绩挪给 Excel。

暂不接收 `.xls/.xlsm/.xlsb/.csv/.ods`、密码文件、签名工作簿、宏/ActiveX/OLE、外部数据、数据模型、复杂透视图表；CSV 不是简单等价 Excel 格式。普通链接文字与会主动读取的外链关系分别判断。

沿用 30 MiB 输入/输出、200 输出页作为拟定初始预算，另拟最多 50 张表、实际非空单元格 200,000；这些是规划值，未做容量测量，不能先写入对外承诺。实际计数而非信任 `dimension` 或文档缓存页数；ZIP/XML 解压、深度、条目和资源预算沿用 Word 安全原则再针对 XLSX 调整。源文件不变、无隐藏表泄漏、所选范围不漏、数字正确比“有一个 PDF”更重要。

| 验收 ID | 必须证明 |
| --- | --- |
| X-P1 | 选择/拖放/取消选择不上传；显式点击才创建上传；与 Word 主动作层级一致 |
| X-P2 | 默认可见表、选择子集、空表、全隐藏、打印区域、多区域与隐藏行列符合契约 |
| X-P3 | 原设置、横向、一页宽、一页内缩放均对照实际 PDF；多表混合设置互不污染 |
| X-Q1 | 至少 20–30 份冻结合成 XLSX，与 Microsoft Excel 实际导出逐页比对；保留原输入、参数和失败分母 |
| X-Q2 | 数字、金额、日期、前导零、大整数文本、公式缓存/重算、跨表引用和缺字独立核对 |
| X-Q3 | 末列/末行、合并格、跨页表头、边框、选中范围、图表/图片均有位置与目视检查 |
| X-S1 | 坏 ZIP/伪扩展名/超预算/宏/外链/密码拒绝；禁网、跨任务访问及隐藏表不泄露 |
| X-L1 | 冷启动、排队、重复更新、取消、超时、崩溃后无容器/临时文件残留；Word 任务不受饿死影响 |
| X-U1 | 320/390px 与桌面、键盘/读屏、真机选择器、下载打开、过期/返回/新任务完整流程 |
| X-R1 | Word 和所有已验收工具累计回归；精确提交 CI、独立输出及真实设备限制如实记录 |

## 6. 下一阶段顺序

1. 用同一组许可明确的合成工作簿补齐 iLovePDF、Smallpdf、Adobe/PDF24 的完整任务观察：选择、设置、预览、执行、下载、重做、取消、坏输入、窄屏与键盘；记录实际按钮、默认值和失败结果。
2. 在现有固定核心镜像做 Excel PoC，优先攻克隐藏表、工作表子集、打印区域、长宽表和公式；保留 Excel 实际参考 PDF。确认接口限制后再决定 OOXML/UNO 适配。
3. 根据证据冻结 UI 可用选项，建立与 Word 一致的可点击原型并自查；本报告中的布局是设计规格，不是已完成可用性测试。
4. 产品开发、单元/集成/边界、累计回归、独立输出和真机验收后交付候选。研究不自动授权正式发布，也不允许上传私人工作簿到竞品。

推荐已明确：**产品选 C，技术复用 Stirling 开源核心版 + LibreOffice，预览与分页可控作为 Excel 的主要差异点。** 完整竞品任务与 Excel 输出实验仍是后续实施门槛。
# 支持范围修正（2026-11-04，用户验收反馈）

原版把图表、图片、条件格式、筛选表一律拒绝，低于常见 Excel 转 PDF 的实用门槛。该限制来自我方预检，而非对固定引擎逐项验证后的结论；不能把缺少测试等同于引擎不支持。原竞品任务研究和显式上传/预览/下载流程继续适用，不另加用户配置或绕路。

本轮在同一 Excel 功能内修正支持矩阵：允许标准 OOXML 常见图表、嵌入 PNG/JPEG、常见条件格式及普通/筛选表；保留工作簿保存的隐藏行、打印区域、图片和图表依赖，仍只导出用户选择的可见表。原件不改，不允许外部取图或外部数据。界面从“一律不支持”改为具体支持范围及“请检查图表、图片、条件格式和筛选行”的保真提示，不承诺像素一致。
