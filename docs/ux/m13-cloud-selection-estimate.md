# M13 云端 Word 转 PDF：技术选型与工期预估

日期：2026-10-28。性质：可选云端路径的研究与估算，不是实施/付费/上传/发布授权。
与[原本地方案](m13-word-to-pdf-design.md)分别保留；不把旧WASM测试当成云端成绩。

## 1. 结论

云端原生Office引擎的部署和服务化路线比当前浏览器WASM候选成熟，能避免手机
下载大型Office资源包、分配WASM内存、受浏览器线程实现约束。它不会自动使任意
DOCX与Word像素一致：字体、域、浮动对象、分节和修订仍须独立验证。

**建议主线：自建 Gotenberg + 原生 LibreOffice，部署在独立AWS转换服务中。**
选择依据是文件处理地区、资源、字体和删除机制可控，按量许可证费用较低；代价是
我们负责服务安全、容量和运行维护。Gotenberg提供容器化Office转PDF接口，
不需要自行维护一套裸soffice进程管理。[官方介绍](https://gotenberg.dev/)

**最快接入备选：Adobe PDF Services Create PDF API。**
其官方支持DOC/DOCX→PDF，转换基础设施由供应商负责；我们仍须实现上传授权、
任务状态、配额、结果交付和数据删除机制。实际版式优劣须用样本比较，不能按品牌
推定。[Adobe Create PDF](https://developer.adobe.com/document-services/docs/overview/pdf-services-api/howtos/create-pdf/)

建议先用2—3工作日完成自建引擎的合成文档PoC与官方能力/费用复核，作为最终
选型点。托管API的实际试转以已获批准的账号/条款及合成文件为前提；这次没有
注册付费账号、请求API、创建云资源或上传文档。当前推荐是有依据的初选，不是实测排名。

## 3. 推荐技术方案

### 3.1 数据流

现有静态React前端 → 创建任务的轻量API → 私有S3限时直传 → SQS任务队列 →
任务Worker → 私有网络Gotenberg/LibreOffice容器 → 独立PDF校验 → 私有S3结果 →
前端查询状态并获得短时下载授权。

云端PoC可先在本机容器验证引擎；前后端与云资源在方案获授权后才建设。现有静态
站不改成大型单体应用；转换容器与其他业务服务隔离。不在浏览器放API密钥，不让
公网用户直接调用Gotenberg原始接口。
[Gotenberg部署说明](https://gotenberg.dev/docs/getting-started/installation)

初期计算配置建议2vCPU/4GB，原生Linux容器、固定镜像digest与字体清单；这只是
压测起点，不是测得容量。单实例试运行可用独立Lightsail/EC2，按负载与可用性需求
再决定双实例或ECS。无需为首版引入Kubernetes。

Gotenberg官方说明一个LibreOffice实例不能并行转换，因此采用“每实例1个活跃
任务＋有界队列”；并发扩展增加实例，不能只增加Web API线程数。任务超时/卡死
可重启该隔离执行单元，重试须幂等且有上限，确定性坏文档不无限重试。
[并发及重启配置](https://gotenberg.dev/docs/configuration)

### 3.2 输入、字体与隔离

- 首版继续单份DOCX、输入30MiB、输出30MiB/200页；不因引擎支持DOC就自动扩展范围。
- 上传前解释云端处理；服务器验证真实包结构、CRC/路径/解压预算、宏/嵌入对象、
  外部关系和主动域。不能将浏览器扩展名检查作为安全边界。
- Worker不持有任意业务凭据；转换容器非root、临时目录有预算、限制CPU/内存/时长。
  转换器禁止主动外连及访问内部元数据/任意本地路径；由外层Worker搬运受控对象。
- 固定中英文字体及许可，必要时补充日文字体。商业字体的服务端使用与PDF嵌入
  资格需单独核验；缺字/字体替代不能静默宣称原样保留。
- 输出用独立PDF解析器检查有效性、大小、页数和几何；测试再用独立阅读器渲染比对。

Gotenberg当前官方配置说明外连默认较宽松，所以必须显式配置拒绝策略并测试，
不能只运行默认Docker命令后视为可接收任意用户文档。
[配置与外连规则](https://gotenberg.dev/docs/configuration)

### 3.3 任务与数据生命周期

状态为created/uploading/queued/converting/ready/failed/cancelled/expired，浏览器显示
真实上传字节进度，转换阶段不伪造百分比。取消语义区分停止上传、取消排队和终止
执行；后端结果发布绑定任务状态，防止迟到结果覆盖取消。

建议默认：输入在转换完成/失败/取消后主动删除，结果保留最多1小时；用户“立即删除”
可删除服务副本并撤销后续访问。执行中取消须清理临时目录；对象过期由定时清理器
主动执行，S3生命周期只做兜底。若使用预签名URL，应用状态变更不自动撤销已签发URL，
需删除对象或采用校验任务状态的下载代理，且明确用户已下载副本不在服务控制内。

只存必要任务元数据；日志不记录原文件名、正文、文档内容或完整签名URL。转换
对象不进入备份/版本保留。选用版本化桶时必须明确删除版本规则，不能只创建删除标记。
删除时限是拟定产品契约，实施和故障演练后才能写进对外承诺。

所有任务/对象访问绑定有足够熵的临时会话凭证；随机任务ID本身不作授权。匿名服务
需要限速、同时任务上限、上传次数/字节配额和费用阈值。任务API校验Origin和上传
完成状态，队列重投、刷新、双击不能产生重复转换和重复计费。

## 4. 产品与隐私调整

文件选择前明确提示“此工具会将文件上传至我们的服务器进行转换”，标明处理地区、
保留时间与删除入口。托管API路径还须说明第三方处理方及其实际政策。

用户流程：选择文档 → 云端处理说明/必要确认 → 上传 → 排队/转换 → 下载。
其他工具继续保留原本浏览器本地处理方式。修订首页、工具页、隐私声明、FAQ、
分析事件白名单和错误文案，不能保留“所有文件都不会上传”的全站绝对说法。

仅云端方案研究不代表用户已同意上传私人文件或采用某个供应商。当前没有启用上传。

## 5. 工期拆分

1工作日按1名熟悉项目的开发者约8小时有效工程投入估算，包含实现、自审、测试与
修复；有既有云账号与域名基础，不假定已有转换后端。本表为工程判断，不是供应商
承诺。以小流量首版为范围，不承诺未知高并发或所有Word特性。

| 阶段                                 | 自建Gotenberg |    托管API | 交付标准                                                                  |
| ------------------------------------ | ------------: | ---------: | ------------------------------------------------------------------------- |
| 候选PoC、冻结样本、质量与费用初选    |         2—3日 |      1—2日 | 原六类＋约20—30份扩展合成稿，保留成功与拒绝分母；确定字体/地区/供应商限制 |
| 后端、任务、上传下载与清理           |         3—4日 |      2—3日 | 幂等、限速、权限、取消、超时与故障后清理；私有引擎或服务端供应商适配      |
| 前端流程、手机与隐私交互             |         2—3日 |      2—3日 | 上传进度、刷新恢复/过期、下载、下一任务、错误恢复，无旧文件残留           |
| 边界、安全、压测、独立输出及全量回归 |         3—4日 |      2—3日 | 实际坏包/超额/外连/跨任务越权/取消；全部既有功能回归；真实手机验收证据    |
| 部署候选、回滚、观察与修复缓冲       |         2—4日 |      1—2日 | 精确提交CI、隔离配置、删除演练、告警/配额、验收包                         |
| 累计                                 |   **12—18日** | **8—13日** | 达到可上线候选；正式发布另需授权                                          |

自建可演示的转换PoC预计2—3日；包含完整用户任务与初步回归的MVP预计累计
8—12日；达到可上线候选累计12—18日，约2.5—4个工作周。
API路径约1.5—3个工作周，并不等于只写一次HTTP调用。

“真实手机验收证据”包含工程实机检查；产品负责人反馈/确认的等待时间不算已完成。
如果拿不到所需设备，则实机项保留未验证，不能以浏览器模拟替代。
供应商签约、账号配额、字体采购和固定地区开通时间另算。复杂版式超出门槛时在
PoC选型点决定换引擎/限定支持，不以无上限修版式吞掉缓冲。
若另要求跨可用区高可用、突发高并发或企业审计，再预留约5—10工作日，先明确SLO。

## 6. 成本与容量估算

低流量自建试运行建议预留US$30—60/月，双实例及基本运行保障预留US$70—150/月；
这是预算区间，不是报价，未含税、研发维护人工、特殊字体许可和异常流量。
参考官方公开Linux/IPv4套餐：4GB/2vCPU为US$24/月、8GB/2vCPU为US$44/月；
S3、队列、API、监控、负载均衡/快照和超额流量另计，地域/购买时价格须复核。
[Lightsail官方价格](https://aws.amazon.com/lightsail/pricing/)

首版容量必须压测。计算方法：所需实例数约为“峰值到达任务/秒 × 实测平均处理秒数 ÷
目标利用率”，再加故障余量。例：仅用于规划，若平均5秒、峰值10份/分钟、目标
利用率60%，计算为1.39，至少2个活跃实例；这些输入不是已测业务量或性能。
同时检查长文档尾延迟、队列等待和内存上限，不能只用平均值推吞吐。

Adobe官方当前免费测试额度500 Document Transactions/月、文件上限100MB；Create
等操作每50页计一个事务，例如200页转换按4个事务估算，不能把免费额度等同
500份任意长度文件。该配额不替代本项目30MiB契约，也不是正式商业报价。
付费需核验合同、地区、配额及实际消耗。
[Adobe限制与计费口径](https://developer.adobe.com/document-services/docs/overview/limits/)

CloudConvert按转换credits销售套餐，具体数量/任务引擎/时长及价格需报价或实际
成本探针确认，不给出未验证的“每份几分钱”。
[CloudConvert定价](https://cloudconvert.com/pricing)

## 7. 当前完成与下一步

本轮完成官方资料核验、与现有静态前端/本地研究衔接、候选比较、架构、工期和
预算区间。未实测原生云端引擎，没有得到供应商保真排名、实际耗时或服务吞吐。

建议按现有流程推进：补齐云转换竞品完整交互 → 2—3日PoC选型点 → 冻结产品及
技术基线 → 后端/前端实现 → 完整边界/累计回归/独立输出/真机 → 交付验收。
拟优先自建Gotenberg；若主要目标是尽快验证需求且接受第三方处理与按量费用，
改选Adobe API。两条路径都先PoC，不同时建设两套生产后端。
