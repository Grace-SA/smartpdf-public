# PDF → PPT：仅使用 Stirling

可编辑转换只使用自托管 Stirling PDF 3.2.2。已删除 Adobe PDF Services 适配器、凭据读取和页面云转换提示；默认 provider 为 `stirling`，仍必须配置 `SMARTPPT_STIRLING_URL`。旧配置中显式选择其他 provider 时，可编辑转换不可用，不会自动发送到其他服务。

扫描件继续使用本地 PaddleOCR，以及可选的 Unlimited OCR 2 / SoMark OXR 区域复核。请求中的旧语言参数暂时兼容，但不宣称它能指定 OCR 语言。API 不再提供云 OCR 能力。保真图片模式不需要 Stirling。

字体中的 Adobe 版权及 OFL 许可证必须保留；它们不是 Adobe 云转换依赖。此前质量报告中的 Adobe 描述为历史记录，不代表当前运行方案。

本功能仍是独立实验服务，尚未接入生产网站。合并代码不代表通过通用上线验收，也不部署服务。固定样本生成成功率、可编辑文字准确率、结构与位置通过率必须分别报告；图片回退不计为可编辑恢复成功。

本次验证包括 Stirling 请求协议、异常清理、取消与下载权限、旧 provider 拒绝、能力接口及 Chromium/WebKit 结果页面。移除 Adobe 专属测试会减少测试总数，不能将减少的计数误报为跳过测试。完整文档回归和真实 API 的完成状态另行记录；不使用旧版本结果证明新版本通过。

Stirling-only 基线已完成全量回归和真实 API 验收，记录见下文的首次合并请求。本轮完成同行 OCR 片段排序及目录点引线边界修复；真实双栏扫描恢复及客户端字体验证仍需推进。公开数据集标注也需检查漏字、错字和页脚覆盖后，才能用于准确率声明。

## 保存重开的边界修复

全量输出核验后，实际 LibreOffice 保存重开发现表格文字的初始水平误差约 1.996pt，保存时坐标取整后增至约 2.018pt，未通过既定 2pt 门槛。现对超过 1.5pt、且能通过有界平移减少误差的左对齐单行单元格提前校准；每次最多平移 2pt，左右内边距之和保持不变。无法改善的对称误差不反复移动，最终仍需完整文字、逐词 2pt 和整页渲染检查。

增加了保存取整余量、宽度不变和无效重复校准的合成边界测试，表格专项 20 项通过。针对失败场景的两页定向验证已通过实际 Office 导入/保存/重开后的 159 个词位置检查；测试副本中的单元格编辑和 10pt 表格平移由程序准备，不冒充 Office UI 操作。修复后的全量回归及真实 API 仍按同一版本重新验收，不放宽通过标准。

## 同行排序、目录点引线与最终验收

同一行的标题和页码可能因字形高度不同而被按检测框顶部排错。现在仅在方向偏差不超过 1°、水平互不接触、垂直中心两两接近时按同行从左到右排序；重叠、跨行、方向不确定或嵌套区域冲突继续拒绝授权。原文字、数字、标点和源记录保持不变。

目录 OCR 框还可能包含点引线，进而影响文字宽度和位置参照。现在仅对直立、浅色背景、中文结尾且框外至少六个点呈规则间隔的情况，在证实为空白的间隔缩小擦除框；明确识别出的末尾句点保留。代码审查另发现浅色首点可能被忽略，已增加保护：如果预期位置还有连贯的浅色墨迹，不把后面的深色点误当成已识别句点，而是保留该行原图。数字、其他标点、省略号和不确定边界不推断裁切。已证实边界的文字以 1pt 为拟合目标，最终验收门槛仍为 2pt。

新增 34 个合成单元/集成用例，其中同行排序 12 个、引线边界 22 个，覆盖错配数字、跨行/重叠、嵌套冲突、显式句点、浅色/细点、倾斜、非规则引线、暗背景，以及实际幻灯片背景像素保留。最终同版本后端 602 项通过、0 项跳过，覆盖率约 95%；另以固定随机种子验证 1,000 组版面、2,000 次断言。网站与 Linux CI 的最终结果记录在对应合并请求中；未配置 Office/字体的 CI 跳过项不计为 Linux 完整验收。
