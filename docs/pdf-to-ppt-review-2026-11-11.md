# PDF → PPT 后续审查与通用上线门槛

2026-11-11。基线为 `98362af910f57b65884cf29d54135b7aef6bbc04`，继续原功能分支。只提交源码，不合并、不部署，不改变现有 Office 引擎、生产路由或发布授权。当前仍是内部验收版，**尚未达到通用上线标准**。

## 复现、修复和复核

- 原生表格会把 `Revenue 100 / Expense 200` 与 `Revenue 200 / Expense 100` 判作相同：字符和数字的多重集均相等。现在保留原生表格必须同时满足归一化后的有序原文完全一致；不满足的页面继续坐标修复和独立渲染门禁。增加数字、标签、顺序换位及正确表格回归。这仍不等于已验证每个单元格的空间语义。
- OCR 使用浮点边界判断重叠，却使用向下/向上取整后的边界擦除。相邻框的实际擦除像素可能重叠。现在共用同一整数边界函数，并验证水平/垂直/对角小数框、恰好相接及原图像素保持。
- PDFium 文字坐标未减去有效 CropBox/MediaBox 原点，裁剪后常见页面会把可编辑文字放到画布外。现在先平移原点再旋转；0/90/180/270 度均与独立 PageToDevice 映射比对。跨裁剪边界或完全在页外的文字对象保留原始栅格，不把原本不可见的字暴露为可编辑文字。
- 取消接口按读到的旧状态更新并忽略更新失败，存在返回已取消但任务继续可下载的竞争。改为事务内读取并取消当前状态；重复取消不会抢先删除仍由 worker 使用的目录。进程启动失败和退出码为零但未发布结果均明确失败，不留在处理状态。
- Adobe 客户端不再继承环境代理，与显式配置的服务来源一致；未配置转换器在创建客户端前拒绝。基线在带 SOCKS 代理的环境下会把此情形误报为一般转换失败。
- Paddle 不再相信模型目录中可被一起替换的 provenance 文件，改用源码内清单校验两套模型必需文件的大小和哈希。U2 新增固定 revision 的权重、配置、模板、tokenizer 清单；加载前验证并拒绝额外替代文件。哈希校验采用流式读取，模型目录须独立物化，不接受指向外部的缓存符号链接。

修复后进行第二次独立代码审查；重复取消和进程启动失败是复核中发现并再次修复的问题。最终定向复核未发现新增阻断。实际 OCR 模型和生产运行环境未在本轮复测，不能把代码审查结论外推为模型或部署验收。

## 本轮实际验证

- Python 3.12.14、仓库固定依赖。基线实测为 128 通过、1 失败、6 跳过；保留该结果，不覆盖成通过。最终实验模块为 **178 通过、6 跳过**，新增 49 项回归。6 项均为既有 macOS 已安装字体测试，Linux 上未执行。存在既有 Starlette/httpx 弃用警告。`smartppt` 语句覆盖率约 86%，不包含真实模型推理。
- OCR 完整性检查独立运行 20 项合成测试通过，包括空/缺失/重复清单、大小及同长度哈希篡改、替代 tokenizer/权重和加载前拒绝。U2 小文件从固定上游 revision 获取并核对 Git blob；两个权重哈希来自该 revision 的 Git LFS 元数据，没有下载约 6.7 GB 权重或运行 MLX。
- 8 个原创裁剪/旋转合成 PPTX 使用本环境 LibreOfficeDev 26.8 alpha 独立打开和导出，8/8 页数和 `Amount 42` 文字相符。与原 PDF 的页面尺寸最大差值为 0.012604 pt。首次要求浮点尺寸完全相等的辅助脚本失败；随后检查保留了实际差值，没有改动产品容差或把第一次失败隐藏为通过。
- 同一渲染检查每页全图 MAE 约 0.001543，前景 MAE 约 0.38882；字体/基线和抗锯齿仍有差别。已查看源页与独立渲染对照，文字不再因裁剪原点而落出画布。小样本、开发版 LibreOffice 和这些像素指标均不证明通用视觉保真。渲染时有字体缓存不可写告警，未把它当成生产字体验收。
- Python 源码编译检查通过。没有触碰私有用户文件；测试输入均由代码生成，产物与截图不进入 Git。

### 未完成的检查和提交范围

本执行环境无已登录 Git 客户端或完整源归档。通过已授权连接读取准确基线源码，但大体积二进制资产无法在当前连接接口物化。原仓库扫描器在已物化索引上执行时仍会因缺少已批准资产而失败，**不是完整 `repo:check` 通过**。本轮不修改扫描器或资产清单，不把局部测试当作主站累计回归。

提交仅在原 Git tree 上更新已审查的文本源码、测试和说明；比较更新前后的全部 tree，要求每个未列入修改集的 blob、模式和路径保持完全一致，所有二进制资产不变。远端提交与功能分支头须再次验证。准确提交的 CI 状态单独检查；既有账户额度问题或旧提交成功结果不构成本提交 CI 通过。合并和上线继续被上述缺口阻断。

## 通用上线的工程验收目标

以下是工作目标，不是已达到的成绩，也不取代用户发布授权：

1. **常见文档覆盖**：按原生正文、双栏/混合图文、普通及合并表格、裁剪/旋转页、清晰中英扫描和中英混排分组，建立固定身份、有人工作为真值、未参与调参的样本集。原解析器异常回归语料单独统计，不当作客户分布。每组分别报告成功、拒绝、局部图片和整页图片的分母及耗时。
2. **可编辑成功定义**：目标至少 95% 的常见受支持文档满足内容、位置、字体可读性和编辑/保存/重开要求。只生成 PPTX 或以图片保底不计为可编辑成功；复杂图表图片化必须披露。零容忍静默换数、错配单元格、漏页或把低置信度 OCR 当作可信原文。当前未有足够证据声称达到此目标。
3. **逐页质量**：检查顺序、数字及单元格对应关系，而不只比较字符数量。保留失败候选与回退原因；按来源页独立渲染和人工抽检。像素相似度不是语义正确率。倾斜扫描、复杂合并表、公式和字体替换仍需明确界定支持范围。
4. **真实运行环境**：固定 Linux 镜像、稳定 LibreOffice、合法交付字体和三种模型的真实推理回归；验证最大输入、队列、取消、进程中断、重启、上游任务终止、临时文件删除、内存和负载。Mac MLX 或此处开发版渲染不能替代生产平台验收。
5. **产品和发布**：完成主站鉴权、配额/限流、浏览器中断和重复操作、PowerPoint/WPS 编辑、真实移动设备及整站累计回归。通过准确提交的检查、代码审查和用户验收后才评估上线。当前没有新增生产入口。
