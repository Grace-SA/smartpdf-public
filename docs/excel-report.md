# Excel 转 PDF 开发与验收记录

日期：2026-11-05。分支：`feature/excel-to-pdf`。状态：兼容性和显示效果修正 Testing；未合并、未发布，未获得用户真机验收。私有语料清单、统计、内容和对照图仅保留本机，不进入本记录或 CI。

## 产品与实现

依据 [竞品与设计方案](ux/excel-to-pdf-research-2026-11-04.md)，新增独立 Excel 入口，复用 Word 的视觉、任务、取消、下载与删除机制。选择工作簿后在浏览器 Worker 中有界读取工作表名称；不上传、不重算公式、不用 HTML 表格冒充 PDF 预览。点击“上传并生成 PDF”才发送文件。

默认选择工作簿最后保存时的当前可见工作表，可明确全选其他可见表，按原顺序合为一个 PDF；hidden / veryHidden 均排除。保留原打印区域、方向和纸张，可统一选择横竖方向、A4/Letter、适合页宽或尝试整表一页。修改设置会撤下旧预览和下载，显式更新后才能下载新结果。桌面提供工作表目录、实际 PDF 翻页/缩放与分页设置；窄屏上下排列，设置在预览之前，主操作按上传、下载、更新阶段固定在底部。结果操作置于预览上方，并为预览保留高度，避免异步绘制移动正在操作的控件。不假定能可靠推断每张表对应的 PDF 页码。

服务端在现有有界 Office 队列中识别 Excel 任务，使用独立的 `excel_session` Cookie（只限 `/api/excel`）；Word 的 Cookie 范围保持 `/api/word`。每个任务一个隔离 Stirling core / LibreOffice 容器。源工作簿不变；临时副本调整打印字段、表格视觉样式和工作表可见性，保留跨表公式依赖。禁止使用会泄露隐藏表、忽略打印区域的 SinglePageSheets。

Excel 候选在 [固定引擎记录](../config/excel-core.stirling-3.2.2.json)中单独锁定，不替换 Word 的已验证镜像。当前本机候选 JAR 摘要与项目已经核对的官方 core JAR 一致；不是受限完整发行镜像，不引入商业模块、付费服务或新云资源。

Microsoft Excel 原生保存文件的已知版本、主题和计算能力元数据按精确白名单检查，未知扩展继续拒绝。保留 XML 属性值引用的命名空间前缀。转换副本移除不透明的打印机驱动二进制及其引用，保留 OOXML 的纸张、方向、页边距和打印范围，并提示核对；不把打印机驱动数据交给转换引擎。

## 当前支持边界

单个 `.xlsx`，30 MiB 输入/输出、最多 50 张工作表、200,000 个单元格、500 输出页（2026-11-05 经用户批准，Word 仍为 200 页）；另外执行 ZIP/XML 条目、实际解压、结构深度、总节点和检查时间预算。大小上限不是任意复杂文件成功承诺。

支持已验证的普通表格、隐藏行列、合并单元格、打印区域和多区域、基本数字/百分比/日期格式、常用内部公式缓存。根据用户验收反馈，本轮扩展柱/条/折线/面积/饼/环/散点等常见图表、嵌入 PNG/JPEG、常见单元格/公式/色阶/数据条/图标集条件格式、表格预设样式与保存后的筛选/隐藏行。单元格公式使用 Excel 最后保存的结果，打印副本冻结缓存且移除计算链，不重算金额、日期、共享/数组或易变函数；缺失结果仍提示先计算保存。普通命名区域、单元格注释和只读保护允许打印。宏、签名、外部抓取、加密文件、新式图表/未知 Office 扩展仍受限。不能把格式兼容性差异全部当作不支持。

超长表在“整表一页”时仍可能受最小打印缩放限制而输出多页；本机 Excel 参考也出现相同行为。界面与结果警告说明这一点，不承诺强制一页或完全同版。字体和默认打印环境不同会导致分页变化。

前端正式构建默认不公开 Excel；需显式 `VITE_ENABLE_EXCEL=true` 才能构建验收入口。API 默认关闭 Excel，需显式启用。生产发布、目标主机验证与可信 HTTPS 另行授权；本轮没有改生产服务器。

## 质量证据与限制

- 可移植合成案例由 `scripts/excel/fixtures.py`、`quality_fixtures.py` 生成；源字节冻结并记录哈希，生成文件、PDF、页面图和原始日志只留在忽略研究目录，不加入 Git。
- 另用本机 Microsoft Excel 原生创建和保存一份无个人正文的合成报价表，验证真实 Excel 元数据、打印机引用及公式缓存。其 Office 自动元数据仅保留本地，未上传竞品或仓库。
- 25 个可移植案例加 1 个原生 Excel 案例：25 份输出、1 份预期拒绝。拒绝例是相互重叠的列定义，初次转换确有截字，修正后固定保留为拒绝，未更换源文件掩盖失败。
- 独立 PyMuPDF 检查所选内容、隐藏/未选表泄漏、打印区域、末行末列、数字、日期与公式；原生报价合计 77.5、两条明细和所选表核对通过。已查看代表性 PDF 渲染图；不宣称所有字体或任意财务工作簿保真。
- 本机 Microsoft Excel 实际导出参考，与 LibreOffice 输出分开记录。普通超宽长表和 Letter 长表有分页差异；没有将字体/打印环境不同的比较称为像素一致。
- iLovePDF 用同一份无个人信息的合成文件完成选择、显式转换、成功页与实际下载观察；所见结果有下载、重做、删除和云盘入口。没有可见工作表子集或分页设置。Smallpdf 仍主要依据官网说明；本轮选择器尝试未完成，未记为完整任务通过。

## 用户验收项目

### 2026-11-04 支持范围修正的验证

原版拒绝常见图表、图片、条件格式、筛选表的范围过窄，现按用户反馈修正。Stirling API 对 Excel 显式传 `useStirlingOfficeConvert=false`。仅传此参数仍不足：同一镜像直接运行 LibreOffice 也丢图，实验证实 `DisableActiveContent=true` 连内部图表一起禁止。Excel 单独派生镜像允许加载内部图表；Word 的镜像和转换选择不变。宏执行、OLE Automation 禁用、网络/文件系统隔离和所有前检的宏/OLE/外部图像/外部数据拒绝规则保留。不要把允许内部图表误述为允许活动工作簿或外部抓取。

精简基础镜像删除了主题 ZIP，连条件格式箭头图标也缺失；Excel 镜像恢复与当前 LibreOffice 匹配、下载哈希固定的 Colibre 图标包及许可证。LibreOffice 原生导入还丢了表格预设配色；打印副本使用 Apache POI（Apache 2.0）的 60 个标准表格样式定义，展开为单元格视觉格式，保留值、公式、数字格式、显式填充和隐藏行。资源限额：每张图最大 20 MP、总图片 80 MP/200 张；100 图表、每表最多 100 张表格、样式数量及格式处理时间均有界。

## 2026-11-05 通用兼容性与显示修正

私有测试严格留在仓库和 OneDrive 之外的本机目录。样本、文件名、内容、清单、私有统计、PDF、图片和诊断不提交，不传 CI，不上传竞品或聊天图片。私有实验使用本机 Docker unix socket，network=none、无宿主目录挂载、无公开端口，文件由本机复制进入后清理。仓库只记录通用规则与独立合成测试；详细私有结论在本机报告中查看。

修正合法 OPC Default MIME 声明、绝对表格关系、普通命名区域、共享/数组公式缓存、只读保护、普通 VML 注释、被忽略的非打印 XML 映射/动态数组计算元数据和静态自包含 SVG。单元格公式全部冻结为保存值，字符串/空字符串/错误值保持类型，删除计算链和表格自动重算定义。缺失缓存拒绝，不擅自重算或变零。输入校验下拉规则不参与打印，从打印副本移除；普通单元格内容不变。VML 控件、宏、外部内容、脚本/远程引用 SVG 仍拒绝，容量/节点/输出预算未放宽。

Excel 专用镜像增加宋体/黑体/微软雅黑/等线到已安装 Noto CJK SC 的映射，不复制微软字体，Word 镜像不变。预览放大按实际宽度、倍数和设备像素比重新绘制，受像素预算约束，避免仅放大固定低分辨率位图。默认当前可见表，提供全选/清空，缩放移到主设置；不会默默导出所有资料表或强制整表缩成不可读的一页。
