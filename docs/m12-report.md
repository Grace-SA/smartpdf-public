## 实现范围

独立 `/unlock-pdf/` 任务：选择一份 PDF，需要时输入当前密码，生成无密码副本，下载后任务结束。未加密输入说明无需解锁；空打开密码仅在验证实际可访问后免填；错误密码原位重试。Show/Hide、Enter 提交、取消、换文件、二选一离开确认和完成页沿用现有交互。没有阅读器、页面编辑器、跨任务历史或自动传递结果。

使用原锁定的 qpdf WASM 0.3.0，实际 qpdf 12.2.0。常见 RC4-40/128、AES-128、AES-256 R5/R6，user/owner、Unicode、旧 PDFDocEncoding 和前后空格/标点已验证。只对用户给定密码做确定性的编码适配，不猜测未知密码，不扩展其他工具的加密准入。

源和输出的有界 qpdf JSON 可达对象图先核对，再通过普通 PDF 的资源/结构检查。对象编号、xref 和加密状态不视为内容差异；页面、流、导航、标签、图层、表单和附件不能静默丢失。该工具只对全图一致且通过预算检查的未编辑结构作隔离保留，其他工具的拒绝规则不变。

数字签名、认证签名与 C2PA 明确拒绝。需要移除 PDF/A、PDF/X、PDF/UA 声明时单独确认普通副本，未确认不下载。原件不改写。

## 密码及诊断隔离

- 密码只存在当前页面和一次性 Worker 的内存，不写入 URL、文件名、请求、埋点、控制台或持久存储。
- qpdf 的 stdout/stderr 在虚拟文件系统回调中截获，原始诊断不出 Worker；界面仅使用稳定错误类别。
- 保真 JSON 从 stdout 流式收取，达到 16 MiB 即中止，避免先创建无限大的审计文件。复杂文件可能在 30 MiB 输入上限以内仍被明确拒绝。
- 在独立 Worker 中限制锁定 Emscripten 运行时的 WASM heap 增长至 192 MiB，并在所有出口恢复适配；这不是整个浏览器进程的总内存保证。浏览器探针验证实际增长被拒绝后仍能开启下一次正常任务，另以约 67 KB 的加密输入承载 64 MiB 合成压缩对象，验证产品能安全拒绝并恢复。
- Worker 仅可通过内部资源适配读取主线程已缓存的公共 WASM 字节，不允许其发起其他 fetch。保持现有 CSP，不增加 blob connect 例外，不引入外部服务。
- 每次检查或解锁结束、失败、取消、超时后均终止 Worker。清理虚拟文件、密码引用及候选；不能承诺 JavaScript 能证明擦除所有内存副本。
- 输入/输出各 ≤30 MiB、最多 200 页，沿用结构/解码限制和总时间预算。公开引擎字节可缓存，私人输入及密码不缓存。

## 技术门槛与工程证据

浏览器技术门槛在接入产品前完成：两引擎 50 次算法与复杂结构解锁、12 次 R5/旧编码/特殊字符补验、16 次分类和签名/凭证拒绝，另有 26 次错误密码检查；未发现控制台诊断泄漏。独立解析和渲染核对 50 份合成输出、888 页。Node 初始可行性另有 11 份/22 页，不与后续浏览器结果混作同一次检查。

当前产品核心累计：457 项通过，1 项既有可选性能测试跳过。新增模型、真实 WASM 集成、Worker 生命周期与内存限制共 51 项。生成脚本按固定合成源复建变体，加密 PDF 和解密结果不进入 Git。

独立产品输出：33 份、361 页通过 PyMuPDF 核对无密码打开、文本、像素、页数/几何、链接、书签、PageLabels、表单、图层及附件。该核对不由解密引擎自己判定。

本地累计双浏览器回归在加入最后的内存加固前为 486 项通过、4 项既有 WebKit 跳过；加固后受影响的 Unlock 完整专项 62 项全部通过（没有新增跳过）。手机长文件名、导航目录和静默准备也已针对性验证。最终源码仍须通过精确提交的 [GitHub 完整检查](https://github.com/Grace-SA/smartpdf/actions/workflows/ci.yml)，实际运行与验收记录另存；不把这些增量数字直接相加或冒充同一份完整运行。

本机详细日志在忽略的 `.research/m12/`、`docs/evidence/`；浏览器模拟与桌面 WebKit 不记作真实 iPhone 验收。

## 发现和修复的具体问题

1. 锁定 WASM 的密码检查返回码不能机械套用最新版文档：无/错误密码也可能返回 2。现在结合隔离诊断分类，不把错误密码当作未加密。
2. 旧 PDFDocEncoding 的重音密码默认适配失败。按同一已知 Unicode 密码做精确编码后验证通过，不是换密码或暴力枚举。
3. `print`/`printErr` 参数未被该构建接收。改为 `noFSInit`/`FS.init` 回调；不能把默认诊断直接暴露给用户。
4. 原内存 Blob URL 加载触发产品 CSP，造成界面初始化失败。改成隔离 Worker 内的公共字节适配，实际构建及离线验证通过，没有放宽 CSP。先前失败日志保留。
5. 冷加载等待也须可立即取消，不能只在 Worker 启动后响应。现在资源准备、文件读取和运行各阶段都受取消及时间预算约束。
6. 手机长文件名被换文件按钮挤窄。改成稳定的两列信息、独立按钮行，追加 320/390px 长文件名可读宽度与高度回归。
7. 新 FAQ 和安全分类暴露旧测试的固定数量假设。保留旧工具断言，新增精确 FAQ、共享分组名称/顺序及最后工具选择器检查，不以放宽超时、自动重试或跳过断言解决。
8. 加密输入不能只按压缩后的文件大小判断资源需求。补充真实 WASM heap 增长约束和高压缩对象失败恢复检查，保持其他工具、引擎二进制及安全策略不变。

技术探针开发服务器的热更新曾中断检查，之后用稳定静态构建重做；首次浏览器累计检查因手机布局自查主动中止，第二次因已定位的分组数量预期主动中止，均不计为通过。
