# PDF-to-PPT round 15: font proportions and portable Roman glyphs

## Root causes and scoped repairs

The pinned public samples exposed two separate causes of low editable coverage. Neither is fixed by relaxing the content or pixel gates.

1. **Whole-word height fitting overweights capitals and descenders.** Source Helvetica Neue has different capital/lowercase proportions from its substitute. A single union-box height can enlarge already-correct lowercase glyphs. Added one bounded **additive-only** retry using the median of exact corresponding character-height ratios. It preserves whole words and ownership of erased regions. Rotated pages/runs, non-one-to-one Unicode normalization, unknown glyph ownership, mismatched sequences and non-finite/degenerate measurements are excluded. No new fit means no candidate; it does not silently fall back to a different calibration.
2. **Nimbus Roman mapped to a different outline family.** The paper's embedded Nimbus Roman No9 L text previously used a generic Times New Roman substitute. An optional pinned TeX Gyre Termes family, derived from Nimbus Roman No9 L, materially improves matching. Only explicit reviewed family/face names qualify; mathematics and unknown families are not inferred.

The median retry is not a replacement pass: a replacement experiment lost existing verified glyphs and was rejected. The shipped path retains all previous source ranges, text XML and observed pixels and uses the first whole-page error baseline. Existing 2pt geometry, regional pixel, content and final-render gates are unchanged.

## Optional font delivery, provenance and rights

[CTAN's official Termes documentation](https://ctan.org/pkg/tex-gyre-termes) identifies the Nimbus Roman No9 L lineage and GUST Font License. All four TeX Gyre Termes 2.004 OTF inputs have fixed SHA-256 and byte lengths in `termes_font.py`. Binary fonts are not committed, downloaded by the service or taken from uploaded PDFs. Operators supply the complete reviewed family via `SMARTPPT_TERMES_FONT_DIR`; without it the existing policy remains.

The generated `SmartPDF Termes` full TrueType faces use FontTools 4.68.0, preserve complete cmap/glyph coverage, OpenType layout tables, advances, line/caret metrics, upstream copyright and original embedding rights. Names and version identify a derivative. Cubic approximation uses 0.1-font-unit tolerance; TrueType integer rounding can alter outline extrema by one unit, so actual output is still rendered and checked. Fixed timestamps and metadata make generation deterministic.

Full [GFL](https://tug.org/fonts/licenses/GUST-FONT-LICENSE.txt), [LPPL 1.3c](https://www.latex-project.org/lppl/lppl-1-3c.txt) and source/modification manifest are included in package data and delivered font metadata. The source's `fsType=12` editable-embedding flags remain in the font and EOT header, not reset to installable/unrestricted. Explicit editable embedding is limited to reviewed fonts; other restrictions still reject. See [Microsoft's fsType specification](https://learn.microsoft.com/en-us/typography/opentype/spec/os2#fstype).

Local rendering materializes the exact generated bytes used by the EOT payload, for all four styles. The system Nimbus font experiment is not shipped: its documented exception should not simply be extrapolated from PDF/PS to PPT embedding.

## Review fixes and evidence

- Independent review caught `setupPost()` resetting italic angle and underline metrics. Those original values are now preserved and regression-tested.
- Incomplete optional font directories no longer select the new family. Each conversion revalidates input bytes before using cached generated output.
- Every pinned face has 1,053 distinct cmap glyph mappings; no Unicode aliases need splitting. Full cmap, layout-table and advance-data equality are checked.
- Four-style post-embedding LibreOffice rendering verifies actual font identities and text, not just ZIP entries.
- Rights tests retain `fsType=12` and reject restricted, preview-only and other unapproved flags rather than stripping them.
- Wheel build and isolated extracted-wheel execution verify all notices and all four generated faces without relying on source-checkout resources.

Controlled median-fitting evidence on W-9 page 2: **81 → 104 editable source glyphs**, **23 added, zero previous glyphs lost**, 34 → 42 text runs, original baseline retained. Strict region tests pass; this remains very low coverage of the 6,819 independent reference characters.

The six-page public probe and independent Poppler word comparison remain diagnostics, not production/Stirling/OCR or representative-corpus acceptance. Raw PDFs and evidence stay local. Final results and test totals follow below.

## Remaining launch barriers

Scientific-paper pages still have unrecovered text and math, and the dense form instruction page remains mostly raster. Generic embedded fonts, scans with independent OCR, broad real-document coverage, Windows PowerPoint/WPS/Mac behavior and production load/runtime acceptance are not certified. Font availability is an explicit deployment requirement. No merge or deployment is performed; GitHub quota-limited CI is not represented as passing. The sparse local repository checker still reports 129 approved binaries absent from the local index; publication preserves the remote assets.

Do not read character coverage or paired-word counts as overall accuracy. Poppler's font-metric boxes differ from the ink bounds used by the regional renderer; strict independent-box diagnostics remain failed, not waived or reclassified as passes. Source/prior/new visual crops were inspected, and the unchanged local ink/content/pixel gates still apply. Cross-client geometry remains an explicit blocker.

The optional family changes which source words qualify: compared with the previous family configuration, paper pages lose 13/4/20 previously editable glyphs and add 617/430/722 others, respectively. Lost editability remains original source imagery, not missing visible content. This is a documented optional configuration tradeoff, not a claim of monotonic cross-configuration coverage. The median-fitting retry itself loses zero prior glyphs.

Whole-page/foreground MAE for the three paper pages improved from 0.0191555/0.1463711, 0.0139397/0.1036630 and 0.0187808/0.1414114 to 0.0161601/0.1263202, 0.0125288/0.0940433 and 0.0155237/0.1191810. Numeric-token deficits remain visible; no extra numeric tokens were reported. These are small selected-sample diagnostics, not population accuracy estimates.

Final verification: **612 passed, 24 skipped** with real LibreOffice and all pinned optional font inputs, 292.87 seconds. The additional embedding-restriction regression was added after collection and passed in the final **23/23** font test run, giving **613 distinct passing tests**. The 24 Mac-installed-font skips are not passes. Independent median-fitting regression included **63 real-render regional tests**. Wheel build and all four generated-face checks from the extracted wheel passed. The repository checker reports only the known 129 locally absent approved assets; the commit preserves other remote blobs.
