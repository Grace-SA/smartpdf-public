### 实现与可见变化

- 对实际框线和模型预测交叉核验，补回模型漏掉的紧凑表格；重叠预测只有在完整框线、字符保留和数字计数一致时才恢复。单个错误框线候选不再使同页正常表格一起失败。
- 原 PDF 字形与预测内容一致时，恢复横线、引号、项目符号及大小写；不猜测不同的数字或词语。处理软换行导致的 Excel 行高翻倍。
- 分开被误并的上下两张表，消除重复点线造成的假列，并在不越过实际分隔线的条件下恢复多层表头的跨行单元格。WEB-111 由一张混合表变为两张独立表，原文 880、1,440 及两张表的横纵合并已单独核对。
- 只从页面实际可见范围提取框线和文字，修正非零/负页面原点。WEB-183 不再把页面外对象额外导出；左右裁切、偏移原点和负原点有合成回归测试。

没有采用宽松的整表框线替换规则：它曾把多行数值合进一格。保留了数字、单元格预算与几何一致性检查。

### 评分口径与局限

基线为提交 `747010e` 的冻结输出，输入 200 个 ID、SHA-256、模型、依赖、Python、180 秒预算和 2 个基准进程保持一致，最终轮在禁止外网环境运行。评估标注共 201 个 JSON/XML 文件，哈希未变；标注不进入转换引擎。

文字匹配仅忽略空白，不忽略数字、标点、大小写。对齐指标允许跳过未匹配行，但不调换列或行顺序；严格位置指标同时报告。合并指标只覆盖标注中的 271 个非空合并单元格。额外输出不被召回率直接惩罚，因此这些数字不是整体准确率，也不是官方 ICDAR 得分。

这批样本用于定位和修复问题，属于固定回归集，不是独立留出测试集。另 133 份没有逐格真值；公开样本也包含正文、图表、损坏和加密负例，不能用成功生成 XLSX 的比例宣传转换准确率。

### 最终实现

- 独立 `/pdf-to-excel/` 页面与 Node 任务服务：选择文件不上传，显式开始，页范围、工作表布局、OCR、取消、重试、预览、下载、清理、离开确认。
- Docling/Heron + TableFormer V1 accurate 识别文字型 PDF 表格结构；PDF 原文匹配单元格；当位置、维度和完整文字集合一致时，采用 pdfplumber 框线结构。模型不改写或补猜正文。
- 小型无框线表格使用保守列间距补充，要求文字表头及数值内容，排除图表纯数字刻度；清晰中英文扫描网格使用 RapidOCR/OpenCV；旋转页使用 Stirling 3.2.2 并提示复核数字格式。
- 所有值写为文本，保留前导零、长整数、公式样文本；原始 Excel 公式无法从 PDF 恢复。单工作表是依次堆叠，不做跨页语义合并。
- 保留支持的横纵合并、相对列宽、源文字大小与换行；按内容扩展行高，并设置打印适应页宽，避免文字虽存在却被遮住。超出可读显示边界时拒绝。
- 同源与会话隔离、原子并发准入、会话续期、进程超时/取消、过期删除、资源上限。生产缺模型不接单。模型固定 revision、SHA-256 验证；模型及依赖不在转换时下载。

### 独立标注质量评估

67 份 ICDAR 2013 样本具有固定上游的表格数量、区域和单元格标注（[示例来源](https://github.com/camelot-dev/camelot/blob/92777b852e00933a5c4b9ba642601784604356cd/tests/files/tabula/icdar2013-dataset/competition-dataset-eu/eu-002-str.xml)），共 158 个标注表格、14,114 个非空单元格。标注不参与转换，只用于独立评估；未剔除上游标为困难/预期失败的 16 份样本。

| 指标                                |                     结果 | 含义                                                       |
| ----------------------------------- | -----------------------: | ---------------------------------------------------------- |
| 文件级表格数量一致                  |                  66 / 67 | 数量一致仍不证明逐格正确                                   |
| 原始行列位置 + 文字 + 跨度匹配召回  | 10,361 / 14,114（73.4%） | 空白行省略或额外标题会使后续位置整体偏移                   |
| 保持行序对齐后，文字 + 跨度匹配召回 | 12,127 / 14,114（85.9%） | 允许跳过未匹配行，不调换列、不纠正文字；比严格坐标指标宽松 |
| 忽略位置的文字多重集合匹配          | 12,840 / 14,114（91.0%） | 仅衡量内容保留，不能代表结构正确                           |

除单独报告的 exact-text 指标外，以上文字匹配忽略空白差异，不忽略数字、标点或大小写。行对齐用同列文字匹配寻找保持顺序的行配对，可跳过空白、标题以及其他未匹配行；缺失参考单元格仍计入 14,114 的召回分母。输出另有 14,032 个非空单元格，额外输出不会被上述召回率直接惩罚，因此不能把召回率称为整体准确率。评估器测试确认丢失前导零、错列、行倒序、合并丢失或旧文件复用都会减分。上游一个坐标含非法字符，仅在排序时忽略该坐标，其文字仍计入；这是自定义评估，不是官方 ICDAR 得分。

严格坐标与行对齐两种指标同时保留：例如新增表格标题、略去空白间隔行会导致严格坐标失败，但不是整行文字丢失。另有真实内容/结构错误，因此 **143/200 输出率、66/67 表格数量一致率，都不能宣传为任意文档转换准确率**。剩余漏表样本 WEB-111 期望 2 表，仅提取 1 表。尚未完成另外 133 份的人工逐格标注；中文业务票据、银行流水、低质量扫描的代表性仍不足。
