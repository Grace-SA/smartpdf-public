# PowerPoint 转 PDF：本地开发与验证

日期：2026-11-05。分支：`feature/ppt-to-pdf`，基于 `main` 的 `de579d7` 独立开发。状态 **Testing，非 Accepted，未合并、未部署**。用户已授权在前期调研基础上继续开发。本次未改动其他工作目录的 Excel 工作。

最新验收更新：2026-11-06。原生参考对照与两家竞品正常、坏输入、离开上传和重做流程已执行；**图表视觉保真存在未解决差异，iOS Safari 真机尚未验收**。本轮仅更新证据和支持范围，不修改转换实现或镜像。

## 产品与实现

入口 `/powerpoint-to-pdf/`，与现有 Word 共用工具目录、导航、视觉样式、文件选择器、PDF 预览和任务生命周期。单个标准 PPTX，60 MiB 输入、30 MiB PDF 输出，最多 250 张源幻灯片、200 张可见幻灯片。选择与本地基础检查不上传；用户点击 `Upload and convert` 才创建任务并上传。选择时生成不可变字节快照，检查和上传使用同一份内容。

保留原尺寸/比例和可见页顺序，每张可见幻灯片输出一页。隐藏页、备注页和批注不输出；动画静态化。结果突出下载，预览按需打开，转换下一份前删除临时结果。初次设计自查后又根据实际手机布局移除结果页重复的上传说明，避免主下载动作被大量文案挤到下面。最终布局仍需产品负责人和真实手机验收。

支持文本、普通主题/母版、形状、表格、内嵌 PNG/JPEG/受限静态 SVG，以及常见标准图表及其内嵌 XLSX 数据的转换。原生对照发现部分普通图表颜色、自动坐标轴和散点标记大小不同，图表不能按完全保真验收。老 `.ppt`、其他 Office/ODF 格式、宏、密码、签名、嵌入媒体/字体、ActiveX/OLE、远程资源不自动开放。SmartArt、公式、复杂 SVG 特性和 EMF 尚无充分质量证据，不宣传完全保真；遇到未知资源会给出具体不支持提示。

## 固定开源环境与适配决策

配置为 `config/ppt-core.stirling-3.2.2.json`；PPT 专用镜像身份：

`sha256:3c274ecae5cb89ebeaeaf85d9d715f9c69df32b352934ae70a7dd7245a75e9be`。

基于已有开源核心候选 `a6bdc6c64f0f0287043f073cca79bcafd515cc9c5a6786c76a6c4deb2af9e6ee`，保留 LibreOffice 26.2.6.3 与字体，补齐校验锁定的官方 Colibre 图形资源，允许普通内嵌图表但继续阻止宏/OLE 自动执行。构建文件为 `server/ppt/Dockerfile`，`doctor.py` 在构建前后核对身份；重建不会自动修改运行 pin。初轮复用了本机 Excel 候选作 PoC，随后建立独立 PPT 镜像并重跑原样本，不将初轮成绩冒充最终镜像成绩。

**实际转换由该核心容器内的 LibreOffice Impress UNO 完成，未启动 Stirling Java HTTP 包装器。** 这是为明确控制隐藏页、备注、原稿嵌入和演示输出选择的适配；并不宣称现有 Stirling REST 已验证支持全部参数。显式使用 `NEVER_EXECUTE`、`NO_UPDATE` 和 `impress_pdf_Export`。不引入付费转换服务、不调用 Microsoft/Adobe 云接口，也没有更换 Word 或 Excel 的镜像 pin。

每任务非 root、只读容器，`network=none`，无宿主文件挂载和公开端口，2 CPU/2560 MiB/512 PID，RAM 临时目录 512 MiB，总任务预算 120 秒，Office 命令预算 90 秒。源包在进入引擎前有 ZIP/CRC/路径/XML/关系、嵌套图表数据与图片像素预算；Windows 上检查 `orig_filename`，防止库的路径规范化掩盖反斜杠/空字节。

任务服务复用 Word 的同源会话、队列、流式容量限制、过期、取消和清理逻辑；PPT 使用独立 API 路径及 Cookie，拒绝 Word 输出选项。输出先用 Poppler 核对页数与尺寸，再在独立 Node Worker 用 pdf-lib 检查全部页面、附件、批注和活动操作。HTTP 成功不直接作为可下载条件。

**部署边界：** 当前为独立本机 PPT 服务，复用的是任务实现，并非已完成跨 Word/PPT/Excel 进程的全局容量调度。在现有小规格生产主机启用前，必须验证共同资源预算、公平队列、反向代理、HTTPS、目标镜像与清理策略。当前本地工作不授权扩大生产容量或发布。

## 本地运行

先核对 `doctor.py` 所需的基线镜像与 PPT 镜像；若需重建，先验证基线 tag 与配置的 `baselineImageId` 一致，再使用空构建上下文构建 `server/ppt/Dockerfile`，审阅新镜像身份，不自动提升。

后端：`node server/ppt/service.mjs`，默认只监听 `127.0.0.1:4281`。配置 `PPT_PUBLIC_ORIGIN=http://127.0.0.1:4280`。当前共享服务的处理地区与本机标识使用 `WORD_PROCESSING_LABEL` 和 `WORD_PROCESSING_MODE=local`；Windows 可配置 `WORD_WSL` 指向现有 WSL。PPT 存储目录由 `PPT_DATA_DIR` 单独指定，禁止备份。

前端：正常构建后在 `127.0.0.1:4280` 预览，Vite 将 `/api/ppt` 转发到本机 4281。只用于本机验收，不宣称其他设备已经可访问。系统内存紧张时采用单构建线程与逐项测试，不同时运行全部浏览器和 Office 转换。

## 受限静态 SVG 支持

SVG 以图片资源进入同一断网转换容器，不在产品网页中内联执行。依据 [W3C SVG 安全静态模式](https://www.w3.org/TR/svg-integration/)及[外部引用规则](https://www.w3.org/TR/SVG/latest/linking.html)，本实现支持普通路径、形状、文字、静态样式、渐变、裁剪/遮罩及同一 SVG 内部定义引用；采用更窄的元素/属性/样式白名单，不表示实现完整 SVG 标准。拒绝脚本、事件、动画、foreignObject、外部文件/URL、SVG 内嵌 image、字体导入、DTD/实体、样式导入及未知样式函数。遇到不支持内容保留明确错误，不静默删除图形后报告成功。

`svg_check.py` 使用 Python 标准库，无新增下载或运行依赖；只允许 UTF-8 标准 SVG 命名空间，每图最多 4 MiB、20000 节点、32 层 XML、64 个属性/节点，样式表 64 KiB。所有 SVG 计入现有 XML 节点及图像像素总预算。图像最长边 16384、单图 4000 万像素、包内图片合计 1.6 亿像素。内部引用检查缺失/重复 ID、循环、展开深度 64 及最多 100000 个展开节点，并覆盖缓存节点的实际深度；SVG 不能借 `.xml` 图片关系绕过检查。原 60 MiB 输入、30 MiB PDF 输出、ZIP 解压预算、非 root/断网容器和时间限制不变。

原创 SVG-only 样本不含 PNG 回退，包含渐变、蓝色圆形和 SVG 文字。固定引擎导出 1 页；独立 PDF 解析与 PyMuPDF 渲染确认蓝色测试点约为 `(31,63,224)`，目视确认形状与文字出现。SVG 不仅被预检接受，也确实被引擎绘出；此样本不证明所有 SVG 的视觉保真。生成器与拒绝样本是原创内容，不使用私人图片、文字或文件结构制作公共夹具。

安全合成测试覆盖脚本/事件/动画/嵌入文档、外部与相对引用、CSS 混淆/未知函数、缺失/重复/循环 ID、指数及深层引用、编码/实体、节点/大小/像素和畸形样式。扩展检查时发现长畸形样式的正则扫描会变慢，改为线性样式与词法扫描；最终 6 组 SVG 用例约 0.134 秒通过。完整单元/集成 576 项通过；随后最终 SVG 规则与 PPT 服务专项 9 项通过。双浏览器 PPT 专项 10 项通过；原创 SVG-only 文件在本机预览的 Chromium/WebKit 实际上传、转换、预览、下载和删除均通过。类型、应用 lint 与构建通过。最终提交还需累计浏览器 CI，不将前一提交的检查视为覆盖新 SVG 支持。

私人语料验证只在本机非同步临时目录执行，文件名、清单、源文件、PDF、截图、文字明细及私人统计不进入源码、CI 或第三方服务。人工私密版式验收、既有图表保真差异、真实手机和生产容量门槛仍保持未完成。

## 明确不换行文本框的导入修正

`layout.py` 在 Impress 导入后、PDF 导出前，恢复源 OOXML 明确指定 `wrap="none"` 且包含 `spAutoFit` 的文本框宽度自动增长。使用 [LibreOffice TextProperties](https://api.libreoffice.org/docs/idl/ref/servicecom_1_1sun_1_1star_1_1drawing_1_1TextProperties.html) 的 `TextAutoGrowWidth` 属性；不改文字、字号、字体或源文件。允许自动换行的正文、固定框、缩小适配和手动换行不改为强制单行。

修正要求源页序与导入页序数量一致、对象名称在源页与导入页均唯一，且规范化空白后的文字匹配；不处理歧义或被导入器改变文字的对象。组内遍历受 32 层和 20000 对象限制。页范围不一致时在修改前停止，避免把修正应用到错误页。适配模块通过已有标准输入传入同一断网容器，不新增宿主挂载、网络、字体安装或镜像变更。

原创三页精简回归包分别表示不换行、允许换行和显式手动换行：旧版行数 `[5,5,5]`，修复版 `[1,5,2]`。该精简包尝试 PowerPoint 原生打开时发生 COM 错误，未计作原生通过；另建完整标准结构的原创包，固定同一输入后比较，旧版 `[4,4,4]`，修复版与 PowerPoint 原生均为 `[1,4,2]`。这验证换行语义，不表示替代字体的每个字形度量完全相同。
