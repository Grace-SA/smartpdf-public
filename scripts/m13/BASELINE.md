# M13 frozen feasibility baseline — 2026-10-26

This is research, before product implementation. Six synthetic DOCX identities
are generated by fixtures.py; manifest hashes are frozen before engine runs.
No private files, system fonts, server conversion or browser printing.

Compare docx-preview 0.4.1 and LibreOffice WASM wrapper 2.7.2. Mammoth is a semantic
HTML comparator, not a layout engine. Both successes and failures count.

Required quality: every unique marker retained once in body; repeated headers
allowed; explicit two-page inputs stay two pages; section orientation retained;
120-paragraph document and 80-row table paginate with no clipping or missing
content; CJK text retained and visibly legible; image and merged-cell content
remain visible. Missing fonts require a user-visible compatibility explanation,
never an exact-fidelity claim. This marker suite is necessary, not sufficient.

Proposed mobile engineering gate (not a pre-existing contractual limit): at most
512 MiB WASM linear memory and 40 MiB compressed cold engine resources including
the selected CJK font. At 10 Mbit/s, 40 MiB alone costs about 34 seconds before
initialization. Record localhost timings separately; they are not mobile network
measurements. Any larger budget needs an explicit product decision after evidence.
Real iPhone memory/stability tests remain mandatory; emulation cannot pass them.

Probe all document processing with non-loopback traffic blocked and counted.
Probe engine initialization failure, cancellation and corrupt/empty files.
No product UI/route until quality, resource and device gates have evidence.
